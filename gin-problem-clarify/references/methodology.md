## 二、第一步 领域拆解

建立 7 个 MECE 维度扫描框架：

| 维度 | 说明 |
|------|------|
| 基础认知 | 基本概念、原理、常见误区 |
| 实操方法 | 怎么做、用什么工具、什么流程 |
| 适用人群 | 不同人群的差异 |
| 常见障碍 | 容易卡在哪、容易放弃的原因 |
| 效果评估 | 怎么判断做得对不对 |
| 风险与边界 | 什么情况下不该做、什么做法有害 |
| 进阶路径 | 从入门到精通的阶段性问题 |

## 三、第二步 问题识别

信息来源：

- 搜索引擎/社区高频提问（大众关心）
- 专家/从业者常见咨询
- 用户真实反馈和投诉
- 领域内争议性话题
- 学术/行业报告

收集规则：频次 ≥ 2 才纳入，原始表述不改写。

## 四、第三步 去重与合并（新增）

脚本：`scripts/dedupe_questions.py`

### 三条规则

**规则一 语义等价判定**：主体相同 + 目标相同 + 信息需求相同 → 合并
**规则二 泛化合并**：一条是另一条的特例 → 合并为通用表述
**规则三 冲突保留**：看似相同但预设不同 → 保留为两条

### 产出

```
{
  "raw": "合并后/原始问题表述",
  "frequency": 累加频次,
  "merged_from": ["原始1", "原始2", ...],
  "source": "代表来源"
}
```

## 五、第四步 问题判定（修订）

脚本：`scripts/judge_questions.py`

四关串行：

```
关卡1：是否有明确信息需求？
  ↓ 通过
关卡2：是否有可回答的答案空间？
  ↓ 通过
关卡3：是否有行动指向？
  ↓ 通过
关卡4：是否有足够需求频次？
  ↓
  passed: 跨来源≥2 且频次≥2  OR  单来源≥5
  degraded: 其余非零情况
  rejected: 单来源且仅1次
```

### 关卡 1：有信息需求（认知缺口）

淘汰：情绪表达 / 纯主观偏好 / 无意义空泛 / 答案已知的常识
边界判定：`减脂好难，我该怎么办` → 通过（后半句有行动追问）；`减脂好难啊` → 不通过

### 关卡 2：有可回答的答案空间

淘汰：价值观问题 / 不可知问题 / 阴谋论伪科学
边界判定：`力量训练和有氧训练哪个更适合减脂` → 通过；`减脂到底有没有意义` → 不通过

### 关卡 3：有行动指向

淘汰：纯理论/历史 / 与主题偏离 / 过度延伸
边界判定：`体脂率降到多少算健康` → 通过；`减脂原理在物理学上怎么解释` → 不通过

### 关卡 4：频次门槛量化

| 来源类型 | 通过阈值 |
|---------|---------|
| 搜索/社区 | 跨来源 ≥ 5 次 |
| 专家咨询 | ≥ 3 位不同用户 |
| 用户反馈 | ≥ 3 条独立反馈 |
| 学术报告 | ≥ 2 份独立报告 |

## 六、第五步 问题澄清（修订）

每条问题填写五要素：

| 要素 | 说明 |
|------|------|
| 主体 | 谁在问？什么背景？ |
| 场景 | 在什么阶段/条件下？ |
| 目标 | 想达到什么效果？ |
| 约束 | 有什么限制条件？ |
| 边界 | 不包含什么？ |

### 规则

- 五要素全部填写，否则回溯追问
- 主体 ≤ 3 个限定条件，场景 ≤ 2 个
- 澄清后问题必须满足「独立可理解」

### 映射关系

| 澄清要素 | 映射维度 |
|---------|---------|
| 主体 | 适用人群 |
| 场景 | 六大维度之一 |
| 目标 | 效果评估 |
| 约束 | 风险与边界 |
| 边界 | 所有维度（排除） |

## 七、第六步 分层与排序（新增）

脚本：`scripts/rank_questions.py`

### 三维坐标

```
知识深度：L1 认知层（是什么） / L2 方法层（怎么做） / L3 判断层（怎么选）
需求强度：H 高频 / M 中频 / L 低频
覆盖面：适用人群细分 ≥3 / 1-2 / 1
```

### 评分公式

```
优先级分数 = 频次得分×40% + 深度权重×30% + 覆盖面得分×30%

频次：H=10, M=5, L=2
深度：L1=10, L2=7, L3=4
覆盖面：≥3=10, 1-2=5, 1=2
```

### 档位

| 档位 | 分数 | 说明 |
|------|------|------|
| P0 核心 | ≥ 7 | 必须包含，优先产出 |
| P1 重要 | 4-6 | 应当包含，视资源安排 |
| P2 补充 | < 4 | 可作为补充 |

## 八、第七步 输出结构化清单（修订）

字段定义见 `output-schema.md`。

主类型 + 副类型分类：

| 主类型 | 判定标准 |
|--------|---------|
| 知识型 | 是什么/为什么 |
| 方法型 | 怎么做/步骤 |
| 判断型 | 选哪个/好不好 |

副类型：比较型 / 评估型 / 风险型（可选，最多一个）

## 九、第八步 验证与迭代（新增）

四种验证方式：

| 方式 | 标准 |
|------|------|
| 用户回访 | ≥ 70% 「是」或「部分是」 |
| 专家审核 | 评分 ≥ 4 分（5 分制） |
| 覆盖率检查 | 每个维度 ≥ 1 条 P0/P1 |
| 去重复检 | 重复率 < 5% |

迭代规则：

- 某维度覆盖率为 0 → 回到第二步
- 用户满意度 < 70% → 回到澄清环节
- 专家评分 < 4 → 回到判定环节
- 重复率 ≥ 5% → 回到去重环节

迭代周期：小版本两周一次，大版本季度一次，主题变更立即重跑。
