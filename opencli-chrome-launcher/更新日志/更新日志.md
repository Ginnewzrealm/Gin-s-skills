# 更新日志

## v1.2.0（2026-09-01）

**修复 cleanup 误关用户窗口的 bug**

- 第三阶段新增：使用 System Events 通过窗口标题（含 "OpenCLI Browser" 群组）识别 OpenCLI 自动创建窗口，关闭映射时跳过空名称 SE 窗口（SE 与 Chrome 索引不对齐）
- 第二阶段收紧：只把 `about:blank` 视为泄露窗口，不再把 `chrome://newtab/` 误判为泄露（用户的合法页面）
- 修复后 cleanup_leaked_windows 能正确保留用户 session 窗口，只关闭 OpenCLI 扩展自动创建的窗口

## v1.1.0（2026-09-01）

**支持 Chrome 关闭状态下的初始化**

- init 模式：移除 `opencli doctor` 前置检查；当 `opencli profile list` 为空时，从 Chrome Local State 自动选择目标 Chrome profile 并写入 binding（OpenCLI profile ID 留空）
- init 模式：`_parse_profile_list` 修复误识别 "No Browser Bridge profiles connected." 提示语为 profile 的 bug
- use 模式：binding 中缺少 OpenCLI profile ID 时，自动启动 Chrome 到目标 profile，轮询检测 connected profile ID 并写回 binding
- use 模式：增加 `_detect_opencli_profile_after_launch()` 方法
- 测试：新增 chrome-only profile 选择测试和验证

## v1.0.0（2026-09-01）

**OpenCLI Chrome Launcher 初版**

- 新增 check / init / use / cleanup 四种独立模式
- 自动检测 Chrome profile 与 OpenCLI profile 绑定，生成 `config/binding.json`
- 支持 Chrome 未运行时启动、错误 profile 时强制退出并重启
- use 模式前置 cleanup，防止 "OpenCLI Browser" 标签分组累积
- cleanup 模式先释放 OpenCLI browser session，再两阶段清理残留窗口
- 增加文件锁，防止多 Agent 并发操作 Chrome
- 输出统一 JSON 结构，方便下游 OpenCLI 技能调用
