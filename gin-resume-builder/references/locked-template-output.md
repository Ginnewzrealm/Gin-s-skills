# 锁定模板的正式输出

适用于中文简历的 HTML 正式输出。主题和信息结构分别处理；不可为压缩页数删字段、减少业绩，或擅自增加装饰。内容人工终审仍按 SKILL.md 执行。

## 数据与顺序

`resume.json` 使用 `basic` + `sections`，不是旧 `basic_info/work_history` 格式。

| 必备项目 | 接收字段（左侧优先） |
| --- | --- |
| 姓名 | 姓名 |
| 联系电话 | 联系电话、电话 |
| 邮箱 | 邮箱 |
| 居住地 | 居住地、城市 |
| 求职职位 | 求职意向、求职职位、职位 |
| 学历 | 教育背景、学历；也可从教育背景板块或旧 education 数据取得完整教育摘要 |
| 年龄 | 年龄（原样输出，不根据毕业年份推算） |

教育字段原文保留；已有教育章节继续保留全部学校、专业、学历和时间，顶部同时展示学历摘要，不再筛选最高学历或删除章节。

姓名单独显示，其下按电话、邮箱、居住地、求职职位、学历、年龄的顺序输出；空间不足时自然换行。相同信息的多个字段别名只输出一次。别名冲突应在组稿和人工终审时解决。

岗位匹配或岗位胜任保留用户确认的板块名称，必须非空，排在联系方式之后、工作经历之前；兼容核心亮点、个人优势。每条推荐使用 `{"tag":"能力小标题","text":"方法与价值说明"}`，长小标题也不会丢失。

工作经历：核心职责 → 关键业绩（能力小标题 + 正文）→ 专业能力 / 荣誉奖项（可选）。项目经历：项目描述 → 职责与行动（能力小标题 + 正文）→ 成果与影响（可选）。技能支持 `groups` 或 `items`，保留技能分组小标题。`groups` 按“能力标题：正文”逐行紧接显示，换行从正文起点对齐。工作和项目 bullets 同样支持 `{tag,text}`，长标签用此结构，避免超过字符串冒号前缀的 32 字识别上限。核心职责、专业能力、项目描述、成果与影响中的已有小标题也须保留；字符串可用“标签：正文；标签：正文”。禁止为了排版凭空新增能力分类。不要用样稿中的虚构资料填补真实简历。

## 调用与主题

```bash
python3 scripts/resume_structure_check.py --resume resume.json
# 按 SKILL.md 展示文字稿并取得明确批准后执行：
python3 scripts/html_renderer.py --resume resume.json --theme editorial --editable --out 简历.html
```

主题为 `minimal`（极简）、`bank`（投行）、`editorial`（欧美）。优先复用用户已确认的风格；主题选择优先级：命令行 `--theme` → JSON 顶层 `theme` → minimal。无须反复让用户确认同一设计。

普通 HTML 与 `--editable` 使用相同版式；编辑开关、保存修改、还原和 PDF 导出均保留。长简历自然分页，不自动压缩为一页。原可编辑母版的逐段编辑/自动适配一页工具不再使用，避免改变锁定字号和间距。

导出 PDF 时使用 HTML 工具栏的“导出 PDF”，打印对话框取消页眉页脚、边距选“默认”、缩放保持 100%。模板以 A4 `@page` 页边距和页面安全内边距共同限定正文区域；长联系方式、职位、字段正文和技能正文允许换行，技能区允许自然跨页。不得重新把打印态 `.page` 内边距清零，也不得用缩小字号、压缩行距或删减内容解决裁切。

在技能根目录保存可编辑母版（目录须先存在）：

```python
import json
import sys
from pathlib import Path
sys.path.insert(0, "scripts")
from html_renderer import save_workspace
resume = json.loads(Path("resume.json").read_text(encoding="utf-8"))
save_workspace(resume, {"theme": "editorial"}, Path("基础简历.html"))
```

`save_workspace` 保持同一主题，缺项校验失败时不覆盖已有母版及配套文档；不要仅记录 `theme_color` 来代替主题。生成页以显式主题启动，不读取跨文件的 `resume-theme` 浏览器缓存。保存后的 HTML 保留当时主题；浏览器正文暂存按文件路径、标题和内容指纹隔离。

## 版式契约

- 采用已确认样稿的极简、投行和欧美规则；后续仅修改用户指出的主题及属性，不跨主题覆盖。
- `.field-label` 是字段标签，`.field-content` 是完整正文容器。核心职责、专业能力、项目描述、成果与影响采用“字段标签：正文”紧接布局，自动添加全角冒号；关键业绩、职责与行动继续使用独立标签。含数字或内嵌小标题的正文不能拆成多个 Grid 子项。
- `.bullet-tag` 用于业绩、行动、岗位匹配小标题；`.ability-tag` 用于字段正文内小标题；`.skill-label` 用于技能分组。正文数字不自动加粗。
- 板块以 `data-section` 标识 competencies/work/projects/skills；禁止依赖第几块的 `nth-of-type`，否则加上岗位匹配后工作经历会套错样式。
- 极简、欧美不用蓝色文字或字段灰块；投行保留已确认的藏青金色。欧美区块无左侧竖条、联系方式下单线、相邻经历只用单根分隔线。
- 字段标签保持单行，正文紧随冒号；多行正文从正文起点对齐。技能分组每行独立计算标题宽度，不使用会造成大空档或重叠的固定宽度标签列。不得为了迁移模板改写已确认的简历事实。
- 打印态有效左右边距保持 18mm，页面容器保留 6mm 安全内边距；长字符串使用换行兜底，整个技能区不得设置为禁止跨页，单条技能可避免页内断裂。

## 必检与失败处理

正式 `render()` 和 CLI 会检查七项基本信息及非空岗位匹配/岗位胜任。缺项明确报错，CLI 退出码 2，已有输出不覆盖。结构检查仍检查工作与项目经历的字段和条数；数字与技能的事实真实性、责任层级和用户终审继续由原管线负责。

`render(..., validate=False)` 仅供既有高管骨架内部使用，不是正式中文简历的绕过方式，CLI 不提供此开关。不得用占位文字通过必检。

复用旧工作空间时，保留已确认的内容、板块顺序及用户选择的主题；旧 HTML 如果缺少字段正文容器或使用旧的单页模板，应经本渲染器重建其版式，并明确告知用户。不要直接复制旧 CSS 覆盖锁定模板。

测试：`python3 -m pytest tests -q`。验收数据是 `tests/fixtures/locked_resume.json`（全部虚构），包含完整头部、岗位匹配、两段工作、两个项目和技能分组。检查三主题、普通/编辑版、缺项拦截、主题持久化、别名去重、长小标题与换行、正文数字和字段对齐。自动测试通过不等于已视觉验收；浏览器或打印检查受阻时必须说明。
