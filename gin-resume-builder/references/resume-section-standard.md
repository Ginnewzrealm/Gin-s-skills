# 简历板块字段标准（输出质量的核心规范）

> 每份简历输出必须遵守本文件：字段结构、写作公式、合格线。
> 组装 resume.json 前读本文件；组装后运行 `scripts/resume_structure_check.py` 校验，通过才允许渲染。
> 面向商务 / 管理岗为主的设计；技术岗可把「专业能力」内容换成技术栈，结构不变。

## 总则

1. 每个板块 = 固定字段 + 写作公式 + 合格线，不自由发挥
2. 真实性底线：所有数字、荣誉、头衔必须是知识库硬事实，过溯源校验后才能上简历
3. JD 定制：与目标岗位最相关的经历排最前，bullet 按 JD 相关度排序，用 JD 原词包装
4. 面向商务 / 管理岗：成果可以是数字业绩，也可以是组织影响（建机制、带团队、推流程）

## 一、工作经历（每段 4 个字段标签）

```
公司（可选括注简介）｜职位｜起止时间
【核心职责】一句话
【关键业绩】3-5 条 bullet（带能力小标题）
【专业能力】1-2 行（可选）
【荣誉奖项】0-1 条（可选）
```

### 字段 1：核心职责（必填，一句话）

- 作用：让 HR 三秒知道「你干什么、管多大盘子」
- 公式：**负责【业务范围】，统筹/带领【规模】，对【核心指标】负责**
- 规模信息（团队人数、业务体量、预算量级、汇报线）尽量在这一句给掉，这是 HR 判断段位的第一依据
- 禁忌：不堆动词清单，不写流水账

### 字段 2：关键业绩（必填，3-5 条 bullet）

- 每条结构：**能力小标题 + 强动词开头的动作 + 量化结果**
- 能力小标题（如「业绩增长：」「团队管理：」「渠道拓展：」）让 HR 一眼看清能力维度，标准格式，强烈建议每条都写
- 强动词池：主导、策划、搭建、优化、重构、落地、推动、谈判、整合；禁用「参与」「协助」开头
- 量化结果三类（商务/管理岗）：
  - 业务规模：管理 X 人团队、覆盖 X 家客户、X 场活动
  - 业绩增长：营收 X 万、提升 X%、翻 X 倍、超额完成 X%
  - 效率/成本提升：周期缩短 X、成本降 X%、人效提升 X%
- 管理岗补充：成果可以是组织影响——「搭建 XX 机制并在 3 个部门推广」「培养 2 名主管晋升」
- 禁忌：「工作能力提升了 20%」这类无法验证的模糊表述；「带领团队」必须带人数

### 字段 3：专业能力（可选，1-2 行）

- 只写该段经历**实际使用**的能力/工具/方法：商务谈判、招投标流程、CRM 系统、数据分析、预算管理、绩效考核体系等
- 与简历底部全局「技能」板块分工：这里管「人看」（场景背书），底部管「机器筛」（ATS 关键词）
- 与经历无关的通用技能不写在这里

### 字段 4：荣誉奖项（可选，0-1 条）

- 必须带含金量限定词：「全公司仅 5% 名额」「集团年度」「破格晋升」
- 没有真荣誉就不写，绝不编造；荣誉是硬事实，必须已在知识库中

### 完整示例（商务管理向）

```
某某商贸集团（国内头部快消经销商）｜大区销售经理｜2021.04-至今
【核心职责】负责华东大区 3 省经销网络的销售与渠道管理，带领 15 人销售团队，
            向销售总监汇报，对大区 1.2 亿年度营收目标负责。
【关键业绩】
- 业绩增长：主导重点客户攻坚与分销体系重构，大区营收从 8000 万增至 1.35 亿，
  连续 2 年超额完成目标，2023 年达成率 118%。
- 渠道拓展：谈判落地 2 家省级头部经销商，新增终端网点 1200 家，
  渠道覆盖率从 55% 提升至 82%。
- 团队管理：搭建销售晨会与跟单辅导机制，团队人均单产提升 30%，
  培养 2 名主管晋升城市经理。
- 回款治理：重构账期管理与逾期预警流程，应收账款逾期率从 9% 降至 2.5%。
【专业能力】商务谈判、渠道体系搭建、销售数据分析（CRM/BI）、年度经营计划拆解
【荣誉奖项】2023 年度集团「金牌大区」（全国 12 个大区仅 2 名）
```

### 责任层级标注

知识库 `work_history.md` / `projects.md` 的每条 bullet 前可用责任层级前缀，供 claim 生成与溯源校验使用：

格式：`- **[层级]** 具体描述`

可选层级（由低到高）：

1. **参与**
2. **负责模块**
3. **主导方案或交付**
4. **项目负责人**

示例：

```markdown
- **[主导]**: 丽水560万合同商务谈判，签约落地
- **[参与]**: 省发改委对接会议，介绍绿城经验
```

claim 生成时会将该前缀映射到 `responsibility_level` 字段；溯源校验时，若前缀声称层级与 `responsibility_level` 不一致则标红。

## 二、项目经历（每个 3 个字段标签）

```
项目名称｜角色｜起止时间
【项目描述】一句话
【职责与行动】2-4 条 bullet（带能力小标题）
【成果与影响】一句话（可选）
```

### 字段 1：项目描述（必填，一句话）

- 公式：**在【背景/难点】下，为【目标】而做的【什么事】**
- 难点是含金量放大器：预算缩减、时间紧、跨部门、从 0 到 1

### 字段 2：职责与行动（必填，2-4 条 bullet）

- 必须写清「**我**」的动作，项目经历最大的坑是「项目很牛、个人贡献说不清」
- 结构同工作经历 bullet：能力小标题 + 强动词 + 量化结果

### 字段 3：成果与影响（可选，一句话）

- bullet 是「分」，它是「总」：收尾点出业务价值或组织影响
- bullet 已把结果说全时可省略；宁缺勿滥

### 完整示例（商务管理向）

```
经销商数字化赋能项目｜项目负责人｜2023.03-2023.10
【项目描述】在预算缩减 20%、涉及 5 个部门的情况下，为提升经销商订单效率
            而主导的数字化订货平台从 0 到 1 落地项目。
【职责与行动】
- 方案设计：调研 32 家核心经销商痛点，设计分级订货与返利自动化方案，
  需求一次性通过率 90%。
- 跨部门协同：作为核心接口人拉通销售、财务、IT 共 5 个部门 20 余人，
  建立周例会与风险清单机制，关键节点零延误。
- 推广落地：制定分批推广与驻场培训计划，3 个月完成 80% 经销商切换上线。
【成果与影响】经销商订单处理周期从 2 天缩短至 2 小时，订单差错率下降 70%，
            项目模式被集团推广至另外 3 个大区。
```

## 三、岗位胜任（置顶板块，2-3 条）

### 定位原则

- 与工作经历互补分工：工作经历证明「做过什么」，岗位胜任证明「具备什么底层能力与做事风格」，两板块内容不重复
- 精准狙击：完全基于目标 JD 要求提炼客观、专业、可验证的底层能力与方法论
- 反个人 IP 化：禁用「操盘手」「破局者」「赋能者」等主观色彩浓厚的自嗨词；能力标签必须客观、可验证
- 知识库存储层叫「个人优势」，展示层统一「岗位胜任」并置顶

### 提炼三步法（拆解 → 映射 → 重构）

1. **拆解 JD**：深度阅读职位描述，提取出现频率最高、最核心的 3 个硬性能力要求（如：数据分析、跨部门协同、项目落地）
2. **映射自身**：在过往经历中寻找能支撑这 3 个要求的核心方法论，做减法，只保留与目标岗位关联度最高的特质
3. **重构表达**：用 JD 中的原词包装，把个人特质转化为客观的「能力维度 + 经验背书」

### 双字段结构（每条怎么写）

**字段 1：能力标签** = 核心能力维度 + 熟练度/经验背书，直接回应 JD 要求。
- 示例：「用户增长与数据分析能力（3 年经验）」「跨部门协同与资源整合能力」
- 标签里的年限/规模背书（如「3 年经验」）视为事实，必须与知识库一致

**字段 2：内容体现** = 做事方法论 + 能交付的价值主张。
- 提炼「做事风格」和「解决复杂问题的通用思路」，**不写具体项目流水账、不带数字**——证据由工作经历的关键业绩承担，此处不重复
- 三个写作角度：
  - 思维模型：「习惯以 ROI 为导向搭建漏斗分析模型」
  - 行为风格：「擅长在多方利益冲突中寻找共赢方案」
  - 交付承诺：「能独立输出数据报告并转化为可落地的业务策略」
- 检验标准：删掉所有形容词后，剩下的方法论描述仍然言之有物；否则就是空话，重写

### 完整示例（目标 JD 核心要求：懂数据分析 / 有跨部门协同经验 / 执行力强）

- **用户增长与数据分析能力（3 年经验）**：具备极强的数据敏感度，习惯以 ROI 为导向搭建漏斗分析模型。擅长在复杂的业务数据中精准定位流失节点，并通过 A/B 测试不断迭代转化链路，能够独立输出数据报告并转化为可落地的业务增长策略。
- **跨部门协同与资源整合能力**：具备优秀的横向推动力，擅长在多方利益冲突中寻找共赢方案。面对历史遗留的推诿问题，能快速梳理权责边界并推动 SOP 标准化，有效降低沟通成本，保障业务高效流转。
- **复杂项目拆解与落地执行力**：拥有极强的项目闭环思维，擅长将模糊的宏大目标迅速拆解为可落地的执行步骤。能够在高压环境下保持冷静，带领团队在逆境中化解危机并超额达成既定业绩指标。

## 四、技能（全局板块）

### 分组方法论

- 按岗位性质自定义 3-4 组，组名就是能力维度的自我声明
- 商务/管理岗常用分组：商务能力 / 管理能力 / 数据与工具 / 语言
- 运营岗常用分组：增长与转化 / 内容与活动 / 数据与工具 / 平台
- 分组标签没有固定清单，写什么组取决于 JD 要什么维度

### 条目表达三档（按信息密度选）

1. **纯技能名**：`商务谈判`——垫底技能、次相关技能用
2. **技能 + 熟练度**（默认）：`商务谈判（熟练）`
3. **技能 + 场景背书**（核心技能用）：`商务谈判（主导 2 家省级经销商签约，单笔 3000 万）`——用经历里的硬事实做证，说服力最强，每组建 1-2 个

### 熟练度措辞标准（不许夸大，面试必验证）

- **熟练**：能独立负责复杂场景，且能带人/定标准
- **掌握**：能独立使用完成工作，不需指导
- **了解**：知道原理、实操少
- 分层失真是面试雷区：写了「熟练」被追问答不上，直接扣分

### 排序与数量

- JD 高频技能前置：组的位置、组内顺序都按与 JD 的匹配度排
- 每组 3-6 个，全表不超过 20 个
- 禁忌：不写与岗位无关的技能凑数；不写「精通 Office」这类无区分度项；不写无法在任何经历里找到佐证的技能
- 来源硬约束：条目必须来自知识库 skills.md（已确认技能）；做简历时新推断的技能，须先按 `references/skills-inventory-standard.md` 的确认门禁经用户确认写入后才可使用

### 与「专业能力」字段的分工

- 全局技能板块（本板块）：管 ATS 机器筛，关键词全、分组清晰
- 工作经历里的【专业能力】字段：管 HR 人看，只写该段经历实际用到的 1-2 行

### 示例

```
商务能力：商务谈判（熟练）、招投标流程（熟练）、大客户经营（熟练）
管理能力：团队搭建与辅导（熟练）、经营计划拆解（掌握）、预算管理（掌握）
数据与工具：CRM 系统（熟练）、Excel/BI 报表（熟练）、SQL 取数（了解）
语言：英语（商务沟通）
```

## 合格线（resume_structure_check.py 的校验项）

| 板块 | 硬性要求 |
|------|---------|
| 工作经历 | 每段有核心职责；bullet ≥3 条；含数字 bullet ≥2 条 |
| 项目经历 | 每个有项目描述；bullet ≥2 条；含数字 bullet ≥1 条 |
| 岗位胜任 | 板块存在且 2-3 条（缺失只警告，非硬失败） |
| 技能 | 板块存在（缺失只警告） |
| 全部 bullet | 无能力小标题只警告；数字必须过溯源校验 |

## 知识库采集约定

访谈采集经历时按同样 4 字段收集，用前缀 bullet 存入原始事实：

```
- 核心职责：负责华东大区 3 省经销网络……
- 主导重点客户攻坚，大区营收从 8000 万增至 1.35 亿……
- 专业能力：商务谈判、渠道体系搭建……
- 荣誉：2023 年度集团「金牌大区」（全国 12 个大区仅 2 名）
```

组装 resume.json 时再把前缀 bullet 映射到对应字段；前缀识别：核心职责：/ 专业能力：/ 荣誉：/ 项目描述：/ 成果与影响：。

岗位胜任条目在 resume.json 中按双字段存储（渲染器显式渲染标签，不依赖正则切分，标签长度不受限）：

```
{"tag": "渠道经营与大区管理能力（5 年经验）", "text": "做事方法论与价值主张……"}
```
