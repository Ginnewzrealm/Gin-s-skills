# JD—证据匹配矩阵方法论

## 目的

在改写简历前，先把岗位描述（JD）的每条要求与候选人的经历证据对齐，决定强调、压缩、删除哪些内容。矩阵让简历定制过程透明可解释。

## 匹配等级

| 等级 | 含义 | 处理方式 |
|---|---|---|
| 直接证据 | 知识库中有明确事实直接对应 | 优先强调，放在靠前位置 |
| 相邻证据 | 有相关经验，但需要桥接 | 改写时建立连接，诚实表述 |
| 弱证据 | 仅有间接关联 | 可考虑压缩或省略 |
| 无证据 | 知识库中没有对应事实 | 标记为 gap，不在简历中编造 |

## 输出格式

```json
{
  "requirements": [
    {
      "requirement": "5 年以上 B2B 销售经验",
      "type": "required",
      "level": "direct",
      "matches": [{"fact_id": "W1", "level": "direct"}],
      "action": "emphasize"
    }
  ]
}
```

## 使用流程

1. 从 JD 中提取硬性要求与优先要求。
2. 对每个要求，扫描知识库 `facts.yaml` 中的事实。
3. 根据关键词重叠与语义关联判定匹配等级。
4. 输出矩阵，展示给用户确认后再进入改写。

## 重要规则

- 矩阵只反映已有证据，不编造新经历。
- "无证据"不等于"不能投"，而是要在简历或求职信中诚实桥接。
- 最终改写仍由 `bullet_rewriter.py` 与 Claude 完成，矩阵仅决定强调方向。
