# Reusable Resume Content

Read this file when an experience has already been written for one or more job descriptions (JDs), or when maintaining reusable wording after an accepted resume.

## Purpose and separation

The evidence bank remains the factual source of truth. A reuse library stores concise, previously accepted ways of presenting verified evidence so later tailoring can start from a strong draft instead of rewriting the same material. It is not a second evidence bank and must not introduce new facts.

Organize entries by `experience + value angle`, such as `community operation + commercialization` or `research + audience insight`. Keep one general expression and at most two or three materially different role-family variants. Do not save cosmetic paraphrases.

## Loading and reuse

- Load only modules relevant to the current job description (JD), not the whole library.
- Check the evidence boundary, ownership, metric date, language, market, and role family before reuse.
- Prefer patching a close accepted version over generating a fresh bullet.
- Company-specific language stays a variant; it does not silently replace the general expression.
- A job-description (JD) route may record which experiences and angles worked for a role family, but only when it adds a genuinely new reusable path.

## Update boundary

Update the library once, after the final resume is accepted, and only when there is a materially new angle, stronger verified fact, corrected metric, or clearly better accepted expression. Run a semantic duplicate check first.

Default to transparent automatic maintenance:

- if a module changes, briefly tell the user what was added or updated;
- if nothing changed, do not announce or perform a redundant rewrite pass;
- ask before replacing a user-confirmed general expression, adopting a stronger or riskier claim, deleting a variant, or promoting company-specific wording to the default;
- respect a user's request to switch to confirm-before-write or manual-only maintenance.

This boundary keeps the library useful without silently spending tokens on repeated content.
