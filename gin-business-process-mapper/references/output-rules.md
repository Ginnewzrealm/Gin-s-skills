# 双格式输出规则

## Markdown

文件名：`<流程名称>-流程说明.md`。

只包含流程标题、场景标题和等宽代码块中的流程树。不得追加概况、角色清单、状态表、证据表、节点附录或说明段落。

场景流程先主场景，再异常和变体场景。每个场景包含：

- 等宽代码块中的树状流程；
- 使用 `│`、`├─`、`└─`、`▼` 和 `◇` 表达顺序、分支和决策；连续步骤必须纵向排列；
- 主责岗位、场景分界线和判断依据；
- 分支之间留空行，续行保持缩进，不把长流程压成一行；
- 节点文案直接写成“岗位在「系统／页面」执行具体操作”或“系统产生具体结果”，不以抽象节点名代替动作；
- 打开页面、选择、填写、点击提交、系统生成单据、更新状态或库存分别占一行；结束步骤末尾标记 `→ 闭环`；
- 每个决策点就地列出判断人、逐条判断依据和无法判断时的处理方式，不在场景底部合并；
- 不使用 `A → B → C` 压缩连续动作。连续动作使用独立行和竖向 `│`、`▼` 连接；决策分支的条件与目标动作也必须分行。

详细字段保留在结构化 JSON 中，不写入交付版 Markdown。

## HTML

文件名：`<流程名称>-流程图.html`。必须是无外部网络依赖的单文件，使用内嵌 CSS、SVG 和 JavaScript。

- 白底、青绿色标题、横向主流程；
- 开始／结束使用圆角节点，日常动作用矩形，决策点用菱形；
- 正常路径居中，分支在上下，异常回流在下方；
- 多场景使用场景切换；打印时依次展开全部场景；
- 每个场景独立计算根节点；多段流程纵向分区，返工线使用独立回流层；
- 连线写清触发条件；
- 节点可点击并定位到同编号说明；
- 支持键盘操作、窄屏横向滚动和打印；
- 节点太多时生成总览加分阶段详图，不无限缩小文字。
- 交付页只显示标题、场景切换和流程图；不显示节点卡片、证据表、条件表、图例或说明段落。

## 信息标记

- `confirmed`：已确认事实；
- `inferred`：根据事实推导的软件含义；
- `unknown`：待确认或待设计。

三种状态保留在结构化 JSON 中用于校验，不在极简交付图中增加说明文字。未来期望不得出现在现状主流程。

## 一致性

两种输出必须来自同一 JSON，并显示相同场景、动作顺序和决策分支。完整节点 ID、规则和证据状态保留在 JSON 中。生成前先运行验证器；验证失败时不得生成终稿。
