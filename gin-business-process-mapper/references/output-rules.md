# Markdown 流程树输出规则

文件名：`<流程名称>-流程说明.md`。

最终只输出一个 Markdown 文档。文档只包含流程标题、场景标题和等宽代码块中的流程树；不得生成 HTML，不得追加概况、角色清单、状态表、证据表、节点附录或说明段落。

## “流程树”的硬性定义

- 每个场景只有一个清晰入口，从入口向下展开完整业务流。
- 普通动作、界面操作和系统结果是动作节点；每个节点只表达一个可观察步骤。
- 打开页面、选择、填写、提交、系统生成单据、更新状态或库存必须拆成独立步骤。
- 判断问题使用 `◇`，判断的每个可能结果都必须成为直接分支。
- 两个分支使用 `├─` 与 `└─`；三个及以上分支依次使用 `├─`，最后一个使用 `└─`。
- 每条分支必须继续展开，直到 `→ 闭环`、明确的“返回某节点”，或访谈确认的流程边界。
- 禁止把同一个判断的不同结果拆成多个场景，禁止只显示“正常”出口。
- 连续动作使用独立行和竖向 `│`、`▼` 连接，不使用 `A → B → C` 压缩流程。
- 分支条件与目标动作必须分行；分支之间留空行，续行保持纵向对齐。
- 节点文案直接写成“岗位在「系统／页面」执行具体操作”或“系统产生具体结果”，不用抽象概念替代真实动作。

## 内容边界

- 交付文档中只显示流程和决策分支。
- 判断人、判断依据、证据来源、状态、规则和待确认项保留在结构化 JSON 中，不写入交付版 Markdown。
- `confirmed`、`inferred` 和 `unknown` 继续用于内部校验，不额外增加图例或说明。
- 未来期望不得混入现状流程树。
- 生成前必须运行验证器；验证失败时不得生成终稿。
