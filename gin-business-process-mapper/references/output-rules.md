# 双格式输出规则

## Markdown

文件名：`<流程名称>-流程说明.md`。

固定包含：流程概况与范围、参与角色与载体、现状流程概览、节点详细说明、决策与异常、状态变化、软件实现含义、产品待设计事项、待确认问题、事实来源。

## HTML

文件名：`<流程名称>-流程图.html`。必须是无外部网络依赖的单文件，使用内嵌 CSS、SVG 和 JavaScript。

- 白底、青绿色标题、横向主流程；
- 正常路径居中，分支在上下，异常回流在下方；
- 连线写清触发条件；
- 节点可点击并定位到同编号说明；
- 支持键盘操作、窄屏横向滚动和打印；
- 节点太多时生成总览加分阶段详图，不无限缩小文字。

## 信息标记

- `confirmed`：已确认事实；
- `inferred`：根据事实推导的软件含义；
- `unknown`：待确认或待设计。

三种状态必须在两种输出中可见。未来期望不得出现在现状主流程。

## 一致性

两种输出必须来自同一 JSON，并包含相同节点 ID、连线、规则和证据状态。生成前先运行验证器；验证失败时不得生成终稿。
