# 双格式输出规则

## Markdown

文件名：`<流程名称>-流程说明.md`。

固定包含：流程概况与范围、参与角色与载体、场景流程、软件操作与状态变化、产品待设计及待确认事项、事实来源、节点明细附录。

场景流程先主场景，再异常和变体场景。每个场景包含：

- 等宽代码块中的树状流程；
- 使用 `│`、`├─`、`└─`、`▼` 和 `◇` 表达顺序、分支和决策；
- 主责岗位、场景分界线和判断依据；
- 分支之间留空行，续行保持缩进，不把长流程压成一行；
- 节点文案优先表达岗位角色、软件位置、界面操作和结果状态。

逐节点字段放在附录，不得取代正文场景树。

## HTML

文件名：`<流程名称>-流程图.html`。必须是无外部网络依赖的单文件，使用内嵌 CSS、SVG 和 JavaScript。

- 白底、青绿色标题、横向主流程；
- 开始／结束使用圆角节点，日常动作用矩形，决策点用菱形；
- 正常路径居中，分支在上下，异常回流在下方；
- 多场景使用场景切换；打印时依次展开全部场景；
- 连线写清触发条件；
- 节点可点击并定位到同编号说明；
- 支持键盘操作、窄屏横向滚动和打印；
- 节点太多时生成总览加分阶段详图，不无限缩小文字。

## 信息标记

- `confirmed`：已确认事实；
- `inferred`：根据事实推导的软件含义；
- `unknown`：待确认或待设计。

三种状态必须在两种输出中可见。未来期望不得出现在现状主流程。

## 一致性

两种输出必须来自同一 JSON，并包含相同场景、节点 ID、连线、岗位角色、软件操作、规则和证据状态。生成前先运行验证器；验证失败时不得生成终稿。
