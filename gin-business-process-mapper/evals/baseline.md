# 无 Skill 行为基线

## 场景

用户只用日常语言描述：收到订单后客服先看，没问题就接单，有问题在微信询问客户；用户明确说不懂软件和流程图。

## 基线响应摘录

基线模型直接补成了“客户补充或修改信息 → 客服再次检查订单 → 确认接单”，随后一次列出四个问题：检查哪些内容、客户不回复怎么办、接单后交给谁、是否无法接单或取消。

## 观察到的失败

1. **自行补全事实**：用户没有说客户一定回复、客服一定再次检查，但响应把它们写进了现状流程。
2. **一次询问多个问题**：四个问题同时出现，不符合非技术访谈的一问一答节奏。
3. **事实与候选场景混杂**：库存、取消订单等合理候选没有标明“待确认”。
4. **过早输出流程**：在流程终点和异常处理尚未确认时，先给出看似完整的流程。

新 Skill 必须针对这些可观察失败提供明确约束。
