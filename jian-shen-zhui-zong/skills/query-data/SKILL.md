# 健身追踪 - 数据查询子技能

## 职责

`query-data` 负责所有**只读查询**场景：

- 查看今日数据
- 查看本周数据
- 查看上周数据
- 查看指定日期数据

**本模块只读不写，不调用 write-verify，不修改任何数据。**

## 执行流程

```
被主技能调用
    ↓
① 发送模块状态反馈：📊 正在读取你的健身数据...
    ↓
② 解析查询目标范围（今日/本周/上周/具体日期）
    ↓
③ 校准北京时间，判断当前时段 T1/T2/T3（规则见 knowledge/polling-rules.md）
    ↓
④ 调用 `lark-sheets` skill 的 `read_header` 模式读取表头行（轮询字段识别与时段归类的基准）
    ↓
⑤ 调用 `DataStore.getUserConfig()` 读取用户配置表，获取目标值
    ↓
⑥ 调用 `DataStore.getDailyRecord(date)` 读取目标日期行数据
    - 内部委托给 `lark-sheets` skill 的 `find_date_row` + `verify_row_values` 模式
    - 命令模板见 `knowledge/sheets-calling-patterns.md` 模式 5 和模式 9
    ↓
⑦ 汇总展示：已填字段、空白字段（今日按三态归类）、完整原始记录、周号、日期范围
    ↓
⑧ 返回结构化结果
```

## 查询范围解析

| 用户表达 | 解析为 |
|---------|--------|
| "今天" / "今日" | today |
| "这周" / "本周" | this_week |
| "上周" | last_week |
| "7月20号" / "2026-07-20" | date |

## 数据读取规则

### 查询模式字段定义调用

- 调用 `lark-sheets` skill 的 `read_header` 模式读取表头行，获取字段名全集
  （表名与表头行范围定义见 `config/sheets-schema.md` 的「每日记录子表」章节）：

  ```bash
  lark-cli sheets +csv-get --url "<fitness.sheets.url>" --sheet-name "每日记录" --range "A1:AQ1" --format json
  ```

- **必须调用 `lark-sheets` skill 的 `read_field_metadata` 模式读取「字段元数据」子表**，获取每个字段的时段、类型、写入方、选项、填写说明
  （表名与范围定义见 `config/sheets-schema.md` 的「字段元数据子表」章节）：

  ```bash
  lark-cli sheets +csv-get --url "<fitness.sheets.url>" --sheet-name "字段元数据" --range "A1:F50" --format json
  ```

- 当需要确认字段类型或选项时，调用 `lark-sheets` skill 的 `read_dropdown_options` 模式读取数据验证下拉选项：

  ```bash
  lark-cli sheets +dropdown-get --url "<fitness.sheets.url>" --sheet-name "每日记录" --range "<col>2" --format json
  ```
- **禁止凭判断只读取部分字段**：展示已填/空白字段时必须以表头行字段全集为基准，否则空白字段清单不可信
- **查询范围包含今日时必须读取字段元数据子表**：时段归类与轮询字段识别都依赖子表中的「时段」列


### 今日时段归类（三态）

查询范围包含"今日"时（range=today，或本周视图中的今天那一行），字段必须按当前时段三态归类：

| 状态 | 含义 | 判定 |
|------|------|------|
| ✅ 已填 | 字段已有值 | 行中有值 |
| ⬜ 应填未填 | 属于当前或已过时段但无值（真正的缺失） | 字段时段 ≤ 当前时段 |
| ⏳ 未到时段 | 属于未来时段，还不到发生时间（不计入缺失） | 字段时段 > 当前时段 |

规则：
- 时段判断与字段→时段映射以 `knowledge/polling-rules.md` 的"字段时段归属规则"为准，本文件不重复
- 历史日期（昨天及更早）是完整的一天，不做时段归类，全部按已填/空白展示
- 查询未来日期：全部轮询字段标记为 ⏳ 未到时段
- 时段归类只适用于轮询字段

### 轮询字段与元字段

已填/空白统计只覆盖**轮询字段**：通过字段元数据子表或字段名可归入晨间/午间/晚间的字段。

元字段（日期、周编号、记录来源、数据异常标记、备注等）不参与已填/空白统计，避免制造噪音。

### 周数据展示

展示本周数据时，必须附带（周号计算规则见 `knowledge/polling-rules.md` 的"时区规则与周定义"章节）：
- Week number（如 `2026-W29`）
- 周起止日期（如 `2026-07-19 ~ 2026-07-25`）

### 展示内容

- 已填字段及其值
- 空白字段列表（今日按三态归类：⬜ 应填未填 / ⏳ 未到时段）
- **完整原始记录 `raw_record`**：包含表头行全部字段，空白字段用 `null` 表示，不得过滤
- 目标值和差异（如用户查询今日且数据完整）

### 展示策略

`query-data` 返回的数据结构同时提供 `filled_fields`、`blank_fields` 和 `raw_record`，由主 `SKILL.md` 的反馈协调器根据用户意图选择展示方式：

| 用户意图 | 展示方式 |
|---------|---------|
| 简单询问"今天填了什么" / "看看今日数据" | 可展示 `filled_fields` 摘要 + 三态归类 |
| 要求"检查"、"看一下"、"审计"、"核对"、"完整数据" | **必须展示完整 `raw_record`**，不得只展示有值字段 |

**原则**：当用户需要判断数据异常、缺失或格式错误时，Agent 不得替用户过滤空白字段。完整原始记录是发现异常（如公式字段被写死、值写错列）的唯一依据。

## 错误处理

- 表不存在 → 返回 `TABLE_NOT_FOUND`
- 日期行不存在 → 该日期标记为"无记录"，不阻塞其他日期展示
- 配置缺失 → 仍展示原始数据，目标值差异部分标注"目标未配置"
