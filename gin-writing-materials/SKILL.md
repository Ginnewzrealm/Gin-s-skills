# gin-writing-materials（写作素材）

> "有材料才写得好。" 本技能只挖素材，不写文章。

## 触发反馈

每次触发先说：

```text
📝 写作素材技能已激活，正在准备挖掘素材...
```

## 落盘纪律（强制）

本技能的核心产出不是对话，而是**可复用的本地素材资产**。以下规则不可违反：

- **禁止只在 Agent 上下文里记忆用户说的话。**
- **禁止等聊完再统一保存。**
- **禁止以"用户没确认"为由跳过保存。** 用户愿意回答，就是愿意记录。
- 用户每轮回答后，只要包含故事、数字、观点、灵感、感受、修正中的任意一种，**必须立即调用 `scripts/save_turn.py` 保存到本地**。
- 每个主题项目必须包含：
  - `00-主题定义.md`
  - `00-需求澄清.md`
  - `01-会话状态.json`
  - `02-素材碎片/`

## Progress Checklist 使用规则

本技能采用 **Progress Checklist** 进度可视化设计。每次触发、每次阶段跳转、每次会话恢复时，必须向用户展示当前进度。

### 设计原则

1. **用户始终知道当前在哪一步**：进入技能后先输出 checklist，高亮当前步骤。
2. **已完成标记为 `[✓]`，进行中标记为 `[ ] ... ← 当前`**。
3. **硬闸门步骤必须等用户明确确认后才能推进**。
4. **支持回环**：用户可以随时要求回退到前面步骤修改。
5. **会话恢复时重新输出完整 checklist**。

本技能允许从一个未成形的灵感开始。不要要求用户先给出完整标题、读者、文体或文章方向；这些信息在素材逐渐成形后再补齐，主题定义文件是可持续更新的快照。

### 步骤标签

| 标签 | 含义 |
|------|------|
| `[自动]` | AI/脚本自动执行，无需用户实时输入 |
| `[需确认]` | 需要用户查看或回应，但不强制阻塞 |
| `[硬闸门]` | 用户不确认则不能继续下一步 |
| `[可回环]` | 用户可以要求回退到前面步骤重做 |

### mine 动作完整流程

```markdown
📝 写作素材挖掘进度

- [ ] Step 1 捕获灵感并创建项目 [自动]
- [ ] Step 2 形成暂定问题（可回环） [需确认] [可回环]
- [ ] Step 3 读取可选锚点素材 [自动]
- [ ] Step 4 确认本次采访方式 [需确认]
- [ ] Step 5 一次一问地采访并保存素材 [硬闸门] [可回环]
- [ ] Step 6 收束确认与闭环校验 [硬闸门]
- [ ] Step 7 生成素材文档 [自动]
- [ ] Step 8 输出素材文档路径 [需确认]
```

### 子动作 micro-checklist

| 动作 | 步骤 |
|------|------|
| `review` | 定位项目文件夹 [自动] → 加载已有素材碎片 [自动] → 展示素材碎片列表 [需确认] |
| `correct` | 定位项目文件夹 [自动] → 加载目标素材碎片 [自动] → 修改素材碎片 [硬闸门] |
| `build` | 定位项目文件夹 [自动] → 加载已有素材碎片 [自动] → 整合生成素材文档 [自动] → 输出素材文档路径 [需确认] |

### 阻塞提示

当流程卡在硬闸门时，输出：

```text
⚠️ 当前阻塞：等待你确认是否沿当前子问题继续（Step 2 形成暂定问题）

你可以：
- 输入 "OK" 或 "确认" 继续
- 输入 "修改" 回退到 Step 2 重写暂定问题
```

### 实现方式

- `scripts/progress_reporter.py`：统一渲染 checklist
- `scripts/stage_validator.py`：决定当前步骤、校验跳转合法性
- `01-会话状态.json`：持久化 `stage` 字段，会话恢复时读取
- 每次推进到下一步时，调用 `session.set_stage()` 更新 `stage`

### 禁止

- 不要把完整主题定义当作对话入口；灵感仍然模糊时可以先记录 seed 并开始采访
- 不要在用户未确认素材价值前标记素材为 confirmed
- 不要等聊完再统一保存（落盘纪律优先）

## 对话主线与提问纪律

每个项目都维护一条主问题（main QUD）和一个当前子问题（current QUD）。每次提问前先在会话状态中记录对象、信息缺口、动作、维度和目的，并在必要时更新 P-X-R：待解释现象（P）、对比预期（X）、希望得到的解释类型（R）。

提问遵循“一次一个问题、先事实后解释、避免诱导”的顺序。可以给出复述或暂定猜测，但必须标注为 AI 的猜测，不能把推导写成用户原话。用户回答后先原样落盘，再用 teach-back 复述并让用户纠正。

出现与主线无关但有价值的内容时，登记为旁支（branch），记录它为什么暂时离开主线以及何时回收；不要为了保持章节覆盖而强行归类。方向可以暂时为空，素材文档会把它放入“未分类素材”。

## 动作路由

| 用户表达 | 动作 |
|---------|------|
| 触发词 + 主题 | `mine`：开始/继续挖掘 |
| "看看素材库" / "我的素材" | `review`：回顾碎片 |
| "这条不对" / "更新这条" | `correct`：修改碎片 |
| "重新生成素材文档" | `build`：生成最终文档 |

## 安装与一次性初始化

本技能需要一次性初始化。安装后或升级后，由用户运行：

```bash
python3 ~/.agents/skills/gin-writing-materials/scripts/init.py \
  --material-root ~/Documents/写作素材库 \
  [--input-materials <文件或目录路径> ...]
```

`init.py` 会完成以下一次性工作，并把结果保存到技能可读取的位置：

1. **保存用户配置**
   - 写入 `~/.config/gin-writing-materials/config.yaml`
   - 核心字段：`material_root`（素材库根目录）
2. **检查运行依赖**
   - Python 版本 >= 3.9
   - `pypinyin` 已安装
3. **检查素材库存储路径**
   - 验证 `material_root` 可写
   - 创建目录结构：`成品/`
   - 旧版 `.gin-writing-materials/` 数据不会被自动迁移，检测到时会提示用户
4. **记录用户输入素材（可选）**
   - 若用户提供了文件/目录路径，验证其存在并记录到配置中

> **备份到当前 Agent 的 tools 目录（可选但推荐）**
>
> 初始化完成后，Agent 应把用户配置额外备份一份到当前 Agent 自己的 tools 目录，
> 防止技能目录被更新/覆盖后丢失用户配置：
> ```
> {agent-tools-dir}/gin-writing-materials/config.yaml
> ```
> 调用 `init.py` 时通过 `--tools-backup-dir` 传入该路径。
> 不同 Agent 平台常见位置示例：
> - Claude Code / Superpowers：`~/.agents/tools/`
> - OpenClaw：`~/.openclaw/tools/`
> - Codex：`~/.codex/tools/`
>
> 日常使用读取配置时，若主配置丢失，会优先查找该 tools 目录下的备份。

> 初始化信息（配置、路径、依赖状态）保存在 `~/.config/gin-writing-materials/config.yaml` 和（可选）`$XIE_ZUO_SU_CAI_TOOLS_DIR/gin-writing-materials/config.yaml` 中，后续使用直接读取，不再重复初始化。

## 启动检查（每次触发）

每次触发 `mine` / `build` / `review` / `correct` 前，只做轻量读取和校验：

1. **读取已保存的配置**
   - 从 `~/.config/gin-writing-materials/config.yaml` 读取 `material_root`
   - 若配置不存在，提示用户先运行 `scripts/init.py`
2. **校验素材库路径**
   - 确认 `material_root` 目录存在且可写
3. **读取用户输入素材（可选）**
   - 若配置或本次对话中提供了素材路径，验证其存在

> 启动检查失败时停止后续流程，向用户报告具体问题（通常是配置丢失或路径不可写）。

## 主流程（mine）

需要格式细节时读取 `references/topic-definition-template.md`、`references/material-template.md` 和 `references/interface-human-writing.md`；提问方法读取 `references/methods.md`。

1. 接收初始输入：可以是标题、问题、经历、观察、情绪或一句思维碎片；原样保存为 seed。
2. **定位/创建项目文件夹**：根据当前可用主题名查找已有 `{material_root}/{日期}-{中文主题名}/` 文件夹；若主题尚不稳定，先用临时名称，后续可回环更新。
3. **形成暂定问题**：调用 `scripts/topic_def.py` 生成或更新 `00-主题定义.md`，只需记录当前问题和已知约束；读者、文体、篇幅允许留空。
4. 读取可选锚点素材（用户已提供或配置中已有的材料）；没有锚点时继续对话，不把联网检索作为默认步骤。
5. 选择采访方式（writing/topic/product/aesthetic/audience），写入 `01-会话状态.json`；方向分类可以延后。
6. 对话循环（8/16/24 轮硬上限）
   - 选方法：读取 `references/methods.md`，从 A-G 中选一种且不连续重复
   - 更新 main QUD、current QUD 和本轮 question plan
   - 提问（可附 AI 猜测，但不得诱导用户接受猜测）
   - 等待回答
   - 追问（最多 2 次）
   - Teachback 复述
   - 用户确认/纠正
   - **记录对话：调用 `scripts/save_turn.py` 把本轮 AI 问题和用户原始表达追加到 `00-需求澄清.md`，并更新 `01-会话状态.json`**
   - **记录素材：用户确认有价值后，再次调用 `scripts/save_turn.py`（带上 `--confidence` 和 `--direction`）生成 `02-素材碎片/{日期}-{序号}.md`**
   - 显示完整性评分（调用 `scripts/validate.py` 中的逻辑）
7. **收束确认**：分别确认知识闭环（用户是否已经得到自己的答案）、公开素材状态（是否允许公开、需匿名或仍未知）和未解决问题；只有用户确认知识闭环后才把素材包视为 ready。
8. 达到收尾条件后调用 `scripts/pipeline.py`。管线会读取 `00-主题定义.md`、运行完整性校验，再整合生成 `03-素材文档.md`；如需单独检查或生成，可分别运行 `scripts/validate.py` 和 `scripts/build_doc.py`。
9. 输出素材文档路径，技能结束。是否基于该素材调用其他写作技能，由用户自行决定。

## 完整性评分

每轮显示：

```text
📊 素材挖掘进度
- 已确认素材：X/5
- 章节覆盖：X/2
- 主题清晰度：X/5
- 知识闭环：open / closed
- 公开素材：unknown / private / anonymize / public
```

## 结束边界

素材文档生成后，本技能任务完成。Agent 应输出素材文档路径，例如：

```text
✅ 素材文档已生成：{路径}

素材整理完成。你可以基于这些素材使用任何写作技能继续创作。
```

**本技能不自动调用任何写作技能**（包括 `human-writing`、`gin-wechat-article-writer`、`gin-wechat-article-core` 等）。是否进入写作阶段，由用户主动决定。

## 边界

- ❌ 不写大纲
- ❌ 不写文章
- ❌ 不搜网络资料
- ❌ 不把多条素材提炼成一条规则
