# 双层逻辑扫描清单

在执行"每轮标准循环"的第 3 步（逻辑扫描）、入档门槛判断、定稿验收时读本文件。

目标：每条新设定过两层检查——单点检查（它自身立不立得住）+ 全局一致性检查（它会不会撞断已有的因果链）。全部检查项使用 Pass / Fail / Repair 三段式输出。

## 输出格式

```markdown
### 🔍 逻辑扫描
- 【单点·因果】④号方向：通过 —— 动机自洽
- 【全局·规则】④号方向：未通过 —— 与已入档第3条"他看到秦朝原主人的真实死亡"冲突

### 🩹 修补方案
- 方案A（最小改动）：……
- 方案B（反转伏笔）：……
```

- 全部通过时只给结论一句话，不逐条铺陈。
- 存在未通过项时必须给修补方案；修补后二选一：入档 / 进待定区。
- 没有未通过项时禁止输出修补段落（不硬凑）。

**关键词中英文对照**（任选其一即可，无需双写）：
- Pass / Fail / Repair
- 通过 / 未通过 / 修复
- ✅ / ❌ / 🩹

评分脚本/读者请用上面三组任一组做匹配即可，避免单一关键词误判。

## 第一层：单点检查（新设定自身）

### 1. 因果链断裂检查

- Pass：设定有合理来源；它的"为什么存在"能一句话答出
- Fail：设定凭空出现，只是"作者想要它有"
- Repair：补一个前置条件或起源（可以很小，但必须存在）

### 2. 战力/能力崩坏检查

- Pass：能力有限制、有代价、有破解方式；对手仍有威胁
- Fail：主角强到剧情没法写；或反派弱到显得主角很蠢；能力无成本无限用
- Repair：加限制（范围/代价/冷却/反制）；或把"全能"拆成"分阶段解锁"

### 3. 动机合理性检查

- Pass：人物做这件事的动机立得住，符合已定性格
- Fail：人物行动只因为"剧情需要"；动机一句话问倒（"他图什么？"答不上）
- Repair：从人物八维（欲望/恐惧/债务/羞耻点）里找真实动机接上

### 4. 代价与约束检查

- Pass：使用设定有成本、有摩擦、有不能做的事
- Fail：设定只给好处不给代价，是许愿机
- Repair：加代价结构（身体/关系/暴露风险/道德成本，任选其一以上）

## 第二层：全局一致性检查（新设定 vs 已有档案）

逐条对照四份档案：

### 5. 世界规则一致性

- Pass：新设定不违反 00-灵魂页的一句话世界规则和 01 档案规则细则
- Fail：需要"世界规则有例外"才能成立，且例外未被解释
- Repair：改设定适应规则，或正式修订规则（修订属重大变更，需用户明确同意 + 波及检查）

### 6. 因果链接续检查（核心）

- Pass：新设定能接进 03 因果链的某一环，且不把后面的环撞断
- Fail：接入后导致已立事件"不可能发生"或"不再有必要发生"
- Repair：调整接入点；或标记受影响的下游环节，提交用户裁决

### 7. 人物一致性

- Pass：新设定下人物行为仍符合其八维画像
- Fail：为了新设定，人物必须做出无铺垫的性格反转
- Repair：补过渡事件（桥），或修改设定保留人物

### 8. 基调一致性

- Pass：新设定落在 00-灵魂页定下的氛围与文笔风格内
- Fail：设定把作品拖向另一个类型（冷幽默悬疑突然变系统升级流）
- Repair：调整设定的呈现方式而非内容；或提醒用户"这可能意味着改基调"，由用户决定

## 因果链验收：改写测试

对 03-主线与因果链.md 中的事件链做逐环改写：

- 把相邻两个事件之间的"然后"改写成"因为 / 所以 / 尽管"
- 改得动 → 该环通过；改不动 → 因果断裂，该环 Fail

示例：

```
E1 他摸到师父遗物看到一段死亡记忆 →【所以】开始私下调查 ✅
E2 开始私下调查 →【然后】藏锋阁派人接触 ❌（缺一环：调查如何暴露了他）
```

定稿第二关要求：全链无 ❌。

## 入档门槛汇总

一条新设定入档需同时满足：

1. 单点检查 4 项全 Pass（或经修补后 Pass）
2. 全局一致性 4 项无 Fail（或冲突已提交用户裁决）
3. 用户明确确认（选择方向 / 说"入档" / 说"都要了"）

任一不满足 → 进 04-待定区，注明原因。
