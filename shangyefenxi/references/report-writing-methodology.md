# 商业可行性分析报告 · 写作方法论（shangyefenxi 子知识库）

> 本文件回答一个问题：**这份报告怎么写——每节写什么、展开到什么颗粒度、怎么保证不同商机输出同样丰满**。
> 10 节框架与证据纪律不动（框架是地基、双层标签是纪律），本文件管"血肉"的深度、形态与**读物化排版**。
> 整合来源：2026-09-06 实战草案（六种信息形态 + 自问自答环）× 深度调研报告（金字塔原理/MECE/VC 尽调标准/Pre-mortem/ACH/IPBES/红队/JTBD/Lean Startup/SSIR，见 `references/deep-research-report-writing-methodology.md`）× hv-analysis 读物排版经验。
> 来源分级：【经典】= 有经典著作或权威机构背书，直接固化；【调研】= 业界调研所得，作启发与判据用；【实战】= 从真实报告对比中归纳。

## 0. 总原则与三层结构

**总原则：宁长勿浅，每个关键判断都值得展开**（hv-analysis 写作精神同款——宁可写长写细，不蜻蜓点水；不为压字数跳过关键判断的展开）。

**定位：读物型报告**。主阅读场景是从头读到尾的深度阅读（用户已确认），排版按读物设计——叙述连续、标题叙事化、表格只做查数点缀；不是跳读型参考手册。

**篇幅基线：全篇 6000–12000 字（字 = 汉字计数，不含标点、空格与 Markdown 符号）。**
- 低于 6000 → 必有关键判断被蜻蜓点水了，逐节回查补写。
- 超过 12000 → 把枝节推演挪去问答挖掘记录，报告正文只留影响结论的部分。
- 统计口径（机械可判，自检第 0 条用同一条命令）：
  ```bash
  python3 -c "import re;t=open('报告.md',encoding='utf-8').read();print(len(re.findall(r'[一-鿿]',t)))"
  ```
- 靠近上限还是下限，看商机复杂度与资料厚度——关键判断的清单见 §4 定级表。

报告每一节内部都是三层，缺层即不合格：

| 层 | 内容 | 服务对象 | 读物型呈现 |
|---|---|---|---|
| **L1 导航摘要层** | 每节标题 + 一句话结论 | 扫读者 | 标题叙事化（见 §1.2），读目录即读全篇判断线 |
| **L2 数据与判断层** | 关键数据、对比、阈值 | 查数者 | **优先「定义列表式数据段」**（见 §1.8）；仅查数刚需保留表格（§1.9 清单） |
| **L3 散文论证层** | 判断链 + 机制解释 + 反直觉点 + 实操模板 | 深读者 | 报告主体，连续成段，不被表格切断 |

当前报告的常见病：L3 缺失或只有一句"笔者认为"、L2 滥用表格切碎阅读流、L1 用主题词不用判断句。本方法论的主体就是给三层各立契约。

**散文密度基线（机械可判，按汉字占比）**：成段散文汉字占全文汉字 **≥55%**，表格汉字 ≤25%。统计命令：

```bash
python3 -c "
import re
L=open('报告.md',encoding='utf-8').read().split('\n')
hz=lambda s: len(re.findall(r'[一-鿿]',s))
tot=sum(hz(l) for l in L)
tbl=sum(hz(l) for l in L if l.strip().startswith('|'))
prose=sum(hz(l) for l in L if l.strip() and not l.strip().startswith(('|','#','>','\`\`\`')) and not re.match(r'^\s*[-*] ',l))
print(f'散文汉字 {prose/tot*100:.0f}%（≥55% 合格）| 表格汉字 {tbl/tot*100:.0f}%（≤25% 合格）')"
```

散文汉字占比 <55% 即「表格吞论证」——重点节的分析被塞进了表格，逐节改写为 L3 段落。

## 1. 通用写作规则（每节都适用）

### 1.1 节首 SCQA（【经典】金字塔原理）

每节第一段（L3 开头）按背景（S）→ 冲突/张力（C）→ 核心疑问（Q）→ 本节结论（A）起笔。读者只看每节首段就能拼出全篇逻辑线。不超过 4 句。
**豁免：定级「薄」的第 1 节不强制四段式**（第 1 节的主体是定义卡，见 §4），以「结论句 + 缺失项影响」两段替代；定级标准/重点的节必写。

### 1.2 标题即结论（【调研】导航层设计研究 + hv-analysis 经验）

**H3 节标题**（`第 N 节 ……`）：判断句，不写主题词。不写「第 4 节 客户画像卡」，写「第 4 节 客户画像：谁让你看懂图纸，订单就给谁」。读 H3 目录即读全篇判断线。
**H4 小节标题**：叙事化判断短语。不写「2.1 市场规模与趋势」，写「2.1 市场不缺流量，缺的是接询盘的能力」。可以是完整判断句或带冒号的判断短语，不是空主题词。
**快速索引的一句话结论列**同理。

### 1.3 以上统下（【经典】金字塔原理，写后检查）

写完后逐层检查：每个子论点是否指向父论点？每个父论点是否有 ≥2 条支撑？下层不得出现"悬空事实"（不指向任何结论的数据点——发现了要么删掉，要么给它接上结论）。

### 1.4 每节自包含（【调研】专业读者行为研究）

决策者只挑 1-2 节深读。每节结尾加一句「本节对整体结论的影响」：只写"加强了/削弱了/条件化了哪个判断"，**一句话封顶**；与整体结论无实际影响的节允许写「无」，不许为凑格式写绕圈子的正确的废话。

### 1.5 决策请求收尾（【调研】Executive Summary 最佳实践）

3 分钟摘要最后一句必须是决策请求句式：**「建议：[行动]，因为 [核心理由]，前提是 [关键假设]。」** 报告不做 Go/No-Go，但要把"要读者做什么"说清。

### 1.6 判断的姿态（【实战】）

下判断用「我的判断是…」「我倾向于…」这种承认主观性的姿态，先摆事实再给判断，推测必须明说。本技能永远不给"做/不做"的结论，只给依据和建议方向。

### 1.7 读者视角禁则（【实战】首测后增补）

报告写给读者，不是写给流程。以下三类内容禁止出现在交付报告里：

- **过程叙述**：「本定义已去掉空转词」「8 维各补一句」「已做 X 轮检索」这类描述"我是怎么写的"的句子——检查动作留在自检清单，报告只交付检查结果（实质内容或整行删除）。
- **未交付档案的指针**：「见 Q19」「挖掘环 Q6 已证」——读者拿不到挖掘记录/运行日志，一律视为死链。需要引用就把内容内联，或删。
- **技能自指**：「本报告为方法论第 N 个实战样本」这类关于技能自身的元信息——属于开发日志，进 CHANGELOG，不进交付物。

**1.2 资料的专门禁则**：资料完整度说明禁止写成采集过程清单——「N 轮检索」「N 个来源」「已覆盖市场与转化率、获客成本……」都是过程视角（相当于 1.7 过程叙述在 1.2 的变体）。1.2 必须写成领域信息覆盖地图，格式见 §1.11。

### 1.8 定义列表式数据段（【实战】hv-analysis 排版经验，读物型的默认数据呈现）

数据密集内容**默认用定义列表式段落**，不用表格——表格的格子线切断阅读流，读物要保持叙述连贯。格式：

```
**转化率**：2.2%——每 100 个访客里，有 2.2 个会发起询盘 ✅
**获客成本**：长尾词 $2.35 ✅ ｜ 泛词 $6.89 ✅ ｜ Bing 洼地 $0.50-2 ⚠️
**决策周期**：打样单 2-4 周 ⚠️ ｜ 量产单均值 130 天 ✅
```

- 每条一行，标签加粗，数据跟后，含义/机制用破折号或句号接着写。
- 置信度标签（✅⚠️❓）**保留在散文正文**——这是证据纪律，读物型不降纪律只降视觉噪音。
- 来源责任标签（[公开数据]/[AI 推测]）**散文正文里不逐条挂**—— L3 只在真正需要标明"这是推断"的判断句挂 [AI 推测]；来源出处收敛到：保留表格的来源列（§1.9 清单内的表）+ 10.2 推断汇总。散文里每个数字后面都挂 [公开数据] 是视觉噪音，纪律已由双层标签 + 来源清单承接。
- 单元格限长规则（≤50 汉字）仅适用于 §1.9 清单内保留的表格。

### 1.9 保留表格的清单（查数刚需，其余一律定义列表式）

读物型不是"去表格化"，是"表格只留查数刚需处"。仅以下位置保留表格：

| 位置 | 保留表格 | 原因 |
|---|---|---|
| 快速索引 + 3 分钟摘要 | ✅ | 扫读导航 |
| 3.2 收入模型 · 3.3 三要素 · 3.4 成本（财务摘要类） | ✅ | 查数刚需 |
| 4.x 客户画像 7 维 | ✅ | 多维对比，定义列表反而乱 |
| 7.1 盲区 · 7.2 风险（Pre-mortem 三件套） | ✅ | 风险台账需结构化 |
| 8.3 阈值 · 8.5 资源盘点 · 8.7 里程碑 | ✅ | 阈值/盘点类 |
| 10.1 发现 · 10.3 未验证 · 10.4 张力 · 10.6 路线图 | ✅ | 决策支撑查数 |
| 2.x 市场 · 5.2 差异化 · 6.1 交付 · 9.1 对标 | ❌ 改定义列表式 | 原表格用长单元格塞论证，是"表格吞论证"重灾区 |

若某商机类型的某处确实更适合表格（如对标数量多、维度杂），允许"一处破例"——但破例理由写入该处下方一行小注，不许默默破例。

### 1.10 卡片与代码块（【实战】）

1.1 / 3.1 的 💡 定义卡**不使用代码块**（等宽灰底在读物里像"代码"不像"内容"）。用普通段落排版：`💡 项目定义` 一行加粗，下接「卖什么 / 卖给谁 / 怎么赚钱」三行各带标签。9.2 的链路流程图（箭头链）保留代码块——它是示意图不是数据。

### 1.11 领域信息覆盖度（1.2 的写法契约，【实战】v1.19 增补）

1.2「资料完整度说明」的**分母是领域本身，不是我们的采集动作**。读者要知道的是「这个业务领域的可行性判断，信息照亮了多大范围」，不是「我们搜了几轮」。

写法契约：

1. **先立分母**：列出该领域的可行性判断需要哪几类信息。维度清单从 10 节骨架反推（半模板化，各商机勾选状态不同即可）：市场需求与规模 / 竞争格局 / 获客成本 / 供给端（工厂、产能、账期）/ 政策与合规 / 财务基准（净利、退货、现金流）/ 客户画像 / 运营基准（响应时效、人力）。维度可按商机增删，但不得少于 5 维。
2. **再报分子**：每维标注覆盖状态——✅ 已覆盖 / ⚠️ 部分覆盖（注明缺哪块）/ ❓ 盲区（注明为什么是盲区）。
3. **给覆盖率判断**：一句话总评（如「六维中四维扎实、两维有盲区」），不许只列状态不做判断。
4. **盲区必须落到结论影响**：每个 ❓/⚠️ 维度跟一句「这决定了哪一节只能给区间/用行业均值/降级处理」——盲区不是免责清单，是结论强度的标定器。

**与 7.1 的分工（防重叠）**：1.2 答「领域哪里没照亮」（覆盖度，定性+范围，篇幅小）；7.1 答「盲区会怎么伤人、怎么补」（影响+补齐动作，风险视角）。同一条盲区两处可出现，但措辞不重复搬运：1.2 说状态，7.1 说后果。

**过程记录归运行日志**：实际做了几轮检索、读了哪些来源，写进 `{商机}/跟踪/运行日志.md`，报告 1.2 一个字不许提。

### 1.12 电子版导航与高亮（路径一落地，【实战】v1.20 增补）

报告主消费场景是电子版（Markdown 阅读器 / 飞书文档），源文件力所能及的导航与高亮做满，做不到的显式归渲染层——**不许在源文件里假装能控制视觉**。

源文件必做（机械可判）：

1. **快速索引锚点跳转**：快速索引表格第一列章节名做成 Markdown 内部链接（`[第一章 事实与背景](#第一章-事实与背景)`），锚点按 GitHub 规则生成（标题文字转小写、空格转连字符、去标点；中文保留）。读者从索引一键到章。
2. **关键判断引用框**：3 分钟摘要的决策请求句（§1.5）、8.6 第零步行动——这两处「读者必须带走的判断」用 `>` 引用块包裹，与正文视觉分层；普通段落不许滥用引用块（全篇 ≤5 处）。
3. **列表嵌套 ≤2 层**：读物型主力是散文+定义列表式，多级嵌套列表是要被压缩的形态；确需层级时到二级为止，再深改写成散文或定义列表式。

显式归渲染层（方法论不管、自检不查）：

- 字体大小/粗细/颜色、标题底色、段落留白、表格斑马纹/对齐/表头底色、✅⚠️❓ 彩色标签样式——纯 Markdown 源文件表达不了，由飞书文档样式与阅读器主题承接；如未来要印刷级控制再考虑 HTML 导出（另行升级，不在本契约）。

## 2. 六种信息形态（血肉的标准件）

> 适用边界：本节两种模式通用——咨询问答模式的每个回答也按此组织（2-3 种形态/回答）；§1/§4/§5 为报告模式专属。

每个重点节至少覆盖其中 4 种；全篇六种都要有。判据是硬性的——"怎么算做到了"可逐条自查。

| 形态 | 定义 | 怎么算做到了（判据） | 来源与修正 |
|---|---|---|---|
| **① 判断链** | 结论 → 依据 → 机制（为什么成立）→ 边界（何时失效） | 每个核心判断能回答"凭什么"和"什么时候不成立"；且优先展示"什么证据会推翻这个结论"（证伪优先） | 【经典】金字塔以上统下 + ACH 证伪优先。比"结论+置信度"多机制与边界两层 |
| **② 反直觉点** | 与直觉相反但有数据支撑的事实 | 能写出"大多数人以为 X，实际 Y，因为 Z"；且按【调研】证据强度规则：争议度越高的主张证据要求越强，反直觉断言自动触发强证据（≥2 独立来源） | 【经典】CIO 证据强度规则 |
| **③ 对比带弱点** | 每个选项/竞品/打法，优点与代价并陈 | 每个对比项都有"但这招的代价是…"；重大判断升级为 **ACH 竞争性假设**：列 2-3 个竞争性假设（如"可行/有条件可行/不可行"），证据矩阵展示各假设的支持/反对，标置信度 | 【经典】ACH 矩阵（升级自实战版"对比带弱点"） |
| **④ 实操模板** | 读者可直接拿走用的动作级产物 | 话术/邮件结构/checklist/流程步骤，具体到"照着抄"粒度；每篇报告每千字 ≥2 个可操作项（【调研】代理指标） | 【实战】问答记录实证：话术级内容是最被用户认可的部分 |
| **⑤ 验收标准** | 每条建议附"怎么知道做对了" | 能回答：成功阈值是什么数字、失败信号是什么、多久复评 | 【经典】Lean Startup 决策阈值预设 |
| **⑥ 风险推演** | 风险 → 触发条件 → 早期信号 → 应对动作 | 不是"有风险"三个字；"当出现 X 信号时，说明 Y 正在发生，应该 Z"；附"关键信号监测清单"（哪些指标变化会推翻当前结论） | 【经典】Pre-mortem 生成法 + ACH 未来观察标记 |

**置信度纪律（与 SKILL.md 硬底线一致，不另起体系）**：✅/⚠️/❓ 标签照打；低置信断言在 L3 必须展开说明"为什么置信度低、需要什么额外证据"，不许只贴个 ❓ 了事。推演型判断标 ⚠️ 起。

## 3. 自问自答挖掘环（写作前的打料工序，硬环节）

**目的**：报告模式的深度不能只靠初稿一遍过。动笔前，Agent 自己向自己提问并回答，把结论往深处再剥 1-2 层。用户只提 9 问、Agent 自问 10 问的那份问答记录（3.50 号档案）证明此机制有效——本环把它从偶发变成必经工序。

### 3.1 问题从五个出口生成（结构性来源，不靠灵感）

**取问源统一为阶段三的《分析结论草案》**（三要素结论 + 画像一句话 + 张力草案 + 关键缺失项清单，存 `{商机}/跟踪/分析结论草案.md`）。挖掘环在动笔之前运行，初稿报告不存在，不得以报告小节（1.2 / 10.4）为生成源。

| 出口 | 生成源 | 示例 |
|---|---|---|
| **盲区追问** | 分析结论草案的「关键缺失项清单」 | "报价区间缺失会怎样改变第 8 节的验证成本？" |
| **张力对攻** | 分析结论草案的「张力草案」 | "痛点强 vs 信任难——市场上有被验证的解法吗？" |
| **反方质询** | 固定模板（每篇必跑），红队三问 | "什么会让你不批准这个方案？""我们最可能在哪里判断错？""要达到可投决级别还缺什么？" |
| **数字追源** | 关键事实卡片中所有 ⚠️/❓ 条目 | "130 天决策周期对本商机适用吗？怎么验证？" |
| **落地追问** | 阶段三每条建议 | "第一步具体做什么？多少钱？什么标准算做对？" |

### 3.2 Pre-mortem 专项（风险节的生成方法，每篇必跑）

【经典】Gary Klein：假设这个商机一年后已经失败 → 独立写出最可能的 5 个死因 → 按"可预见性×影响度"排序 → 逐条转译为"触发条件+早期信号+应对动作"填入 7.2（模板 7.2 列结构即按此设计）。风险不是罗列出来的，是验尸验出来的。

### 3.3 回答纪律（防自欺）

- **推演型**（只用已有材料推理）：必须展示推理链；推不动就标 ❓"此判断暂缺依据"，不许硬答。
- **挖掘型**（需要新材料）：**必须真的联网检索**再答；检索无结果就写"未见公开数据"并给出用户自验方法（如"联系 3-5 家工厂询价"）——这本身也是可执行答案。
- 所有回答带置信度标签。

### 3.4 预算、落盘与停止条件

- 默认预算 **20 问**（可调），每问允许 1-2 轮纵深追问。
- **问题清单先落盘（硬规则）**：开工第一步把编号问题清单（Q1…Q20，每条标注出口）写入 `问答挖掘记录.md` 顶部；作答按编号逐条追加，断点恢复时按编号跳过已答、从未答处续挖——没有清单不许开答（否则"跳过已答"与预算核对无法机械执行）。
- **整批落盘**：每批 3-5 问（或约每 5 分钟）整批追加落盘一次，取先到；答案含问题 + 推理链/检索结果 + 置信度，一行不落。
- 提前停止：连续 3 个问题的答案不再改变任何结论/建议 → 挖到底了，收手。
- 挖掘记录存 `{编号}_{商机名称}/跟踪/问答挖掘记录.md`，作为报告 L3 的取料库；报告成稿后它不交付给用户（用户只要报告），但保留在商机档案里备查。

## 4. 10 节深度契约（每节：呈现层义务 → 展开层义务）

定级原则：定级**重点**的节 = 关键节点，全部适用总原则"宁长勿浅，值得展开"；定级**标准/薄**的节是非关键节点，说透即可，不硬凑灌水。

**重点节 L3 段落契约**：每个重点节的 L3 必须由 **≥3 段连续成段散文**构成——SCQA 首段 + 机制/判断链展开段 + 「本节对整体结论的影响」段；数据用定义列表式穿插（§1.8），不得出现"连续两段以上的论证只存在于表格单元格或列表项"的情况。

| 节 | 定级 | L3 展开层义务（呈现层按 §1.8/§1.9） |
|---|---|---|
| 1 项目一句话定义 | 薄 | 定义卡（非代码块）+ 领域信息覆盖地图（§1.11：分维度标 ✅⚠️❓ + 覆盖率判断 + 盲区对结论的影响）；L3 只补「缺失项对结论的影响」一段（SCQA 豁免，见 §1.1）；1.2 禁采集过程叙述（§1.7 专门禁则） |
| 2 市场调研 | 重点 | 每个关键数字跟"so what"（对本商机意味着什么）；趋势判断每条带机制；至少 1 个反直觉点；市场数据用定义列表式 |
| 3 商业模式拆解 | 标准 | 8 维卡片各补一句"为什么是这个结构"；收入模型按商机阶段调节验证深度（种子期=假设+初步验证，成长期=三角验证【调研】）；3.2/3.3/3.4 保留财务摘要表 |
| 4 客户画像 | 重点 | 7 维表格之上必须有：**一句话画像总结**（"他是一个…的人"）+ 流失触发条件清单 + JTBD 任务定义（客户"雇佣"你完成什么任务）+ B2B 补决策链四角色（经济买家/把关者/使用者/执行者；B2C 换购买旅程地图） |
| 5 价值主张 | 标准 | 差异化每个竞品带"代价是…"；价值主张用 JTBD 反推（先任务后主张）；5.2 差异化改定义列表式 |
| 6 交付清单 | 标准 | 交付物定义列表式 + 补"客户可见/不可见"与复杂度来源 |
| 7 风险评估 | 重点 | 全部风险由 Pre-mortem 生成；每条带机制解释（为什么这个风险在这个模式里必然存在）；风险对称性——每个机会配对下行情景（【调研】Business Case 标准）；附关键信号监测清单 |
| 8 MVP 验证路径 | 重点 | 核心假设按 Lean Startup 四元组重写："我们相信[谁]会[做什么]，因为[原因]；当[指标]在[时间]内变化[幅度]时，我们知道自己是对的"；验证法按三类不确定性分组（需求→技术→商业）；第零步行动必须 30 分钟内可开始 |
| 9 对标对象 | 标准 | 每个对标带"可借鉴/不可借鉴 + 为什么"；链路提炼用箭头流程图（保留代码块，示意图非数据） |
| 10 决策支撑 | 重点 | 10.2 推断说明强制保留（已有）；10.4 每个张力指向具体 MVP 验证；10.6 每个动作带成本+验收标准；新增关键假设清单（每个假设标来源+敏感度【调研】假设日志化） |

## 5. 丰满度度量与成稿自检

### 5.1 客观度量（写后可数）

- **篇幅基线**：全篇 6000–12000 字（字 = 汉字数，命令见 §0）。
- **散文密度**：散文汉字 ≥55%、表格汉字 ≤25%（命令见 §0；读物型基线，§1.9 清单内表格不计入"吞论证"判定）。
- **可操作项密度**：每千字 ≥2 个。**可操作项定义**：以动作动词开头、含具体对象与参数（工具名/数字/阈值）、读者无需再做决策即可照做的条目。正例：「注册 Shopify $27/月店」「首月只投 Bing，预算上限 $1,500」；反例：「做好 SEO」「提升转化率」。写在散文句子中间而非独立条目的，不算。
- **SSIR 证据质量三维度评级**（【调研】Stanford Social Innovation Review）：每个核心断言按 数据/共识/因果链 三维度各评 1-3 级；任何维度 1 级的断言必须补证据或降级为"待验证假设"。
- **形态覆盖**：重点节 ≥4 种信息形态（§2 六选四）。

### 5.2 成稿自检清单（写完逐条过，全部 Yes 才许交付）

> 本清单只管**内容血肉与读物排版**；**结构编号**（第 N 节/x.y/附录）另按 `assets/feasibility_report_template.md` 末尾「写后格式自检清单」逐项过——两份清单都过才算验收完成。

0. 汉字数落在 6000–12000 吗？（命令见 §0）
1. 每节首段是 SCQA 吗（薄节按 §1.1 豁免）？H3 节标题是判断句、H4 是叙事短语吗（§1.2）？
2. 每个核心判断有"凭什么"+ "何时失效"吗？反直觉断言有强证据吗？
3. 风险节是 Pre-mortem 验出来的吗？每条带触发条件和早期信号吗（对照模板 7.2 三列非空）？
4. 客户节有一句话画像总结和 JTBD 任务定义吗？
5. 每条建议能拿走就用吗（按 §5.1 可操作项定义）？每千字可操作项 ≥2 吗？
6. 低置信断言都展开说明"为什么低、缺什么证据"了吗？
7. 有"什么证据会推翻本报告主要结论"的监测清单吗？
8. 3 分钟摘要末句是"建议：[行动]，因为[理由]，前提是[假设]"吗？
9. 每节结尾有「本节对整体结论的影响」吗（一句话封顶，无影响写「无」）？
10. 以上统下检查通过吗（无悬空事实）？
11. 交叉一致性校验跑了吗？五组关系逐项过：市场调研 ↔ 风险评估；商业模式 ↔ 行动路线图；客户画像 ↔ 价值主张；交付清单 ↔ MVP 验证成本；对标对象 ↔ 商业模式同赛道。发现矛盾 → 已在 10.4 标注张力并指向 MVP 验证；没跑过不许交付。
12. 散文密度达标吗？散文汉字 ≥55%、表格汉字 ≤25%（§1.9 清单内表格除外）？哪一节把论证塞进了表格 → 当场改写为 L3 段落。
13. 排版读物化检查：数据密集小节用定义列表式了吗（§1.8）？💡 卡没用代码块（§1.10）？2.x/5.2/6.1/9.1 的表格全部改定义列表式了吗（§1.9）？散文里 [来源] 逐条挂的噪音清了吗（收敛到表格来源列+10.2）？
14. 1.2 是领域信息覆盖地图视角吗（§1.11）？分母是领域信息维度清单（≥5 维），每维标 ✅⚠️❓，有覆盖率总评，每个盲区落到结论影响；且全文无采集过程叙述（「N 轮/N 次/N 个来源」类表述，grep 可验）？与 7.1 分工不重叠搬运（1.2 说覆盖状态，7.1 说影响与补齐）？
15. 电子版导航与高亮（§1.12）？快速索引章节名带锚点且与 H2 文字一致；两处关键判断（摘要决策请求句、8.6 第零步）用引用框、全文 ≤5 处；列表嵌套 ≤2 层？

## 6. 常见错误（来自实战 + 调研）

| 错误 | 纠正 |
|---|---|
| 七维表格填完就走，没有一句话画像 | 画像总结是客户节的灵魂，必须有 |
| 风险是正向罗列的（"可能遇到 A/B/C"） | 用 Pre-mortem 逆向验尸生成，先假设失败；落表时触发条件/早期信号/应对动作三列缺一即不合格 |
| 建议停在"做 LinkedIn 内容"级 | 追到话术/步骤/阈值级（§5.1 可操作项定义） |
| 数字贴完不解释 | 每个关键数字跟"so what" |
| 低置信断言贴个 ❓ 就算交代了 | L3 展开：为什么低、缺什么、怎么补 |
| 自问自答环里自己提舒服的问题、答舒服的案 | 红队三问是固定模板，每篇必跑；挖掘型问题必须真检索 |
| 挖掘环边挖边问、没有编号清单 | 先落盘编号问题清单再作答（§3.4） |
| 交叉一致性校验被静默略过 | 它是 SOP 独立步骤，已挂入 §5.2 第 11 条，自检清单不过不许交付 |
| 全文表格化：表格长单元格塞论证，散文只剩零星"so what" | 数据用定义列表式（§1.8）；表格只留 §1.9 清单；散文密度查 ≥55% |
| 小节标题用主题词（「市场规模与趋势」） | 叙事化判断短语（§1.2）；读目录即读判断线 |
| 💡 卡用代码块，视觉上像代码 | 去代码块，普通加粗排版（§1.10） |
| 1.2 写成采集过程清单（「N 轮检索」「已覆盖 A/B/C」）——过程视角，且与 §1.7 禁则自相矛盾 | 改领域信息覆盖地图（§1.11）：分母=领域信息维度清单（≥5 维），分子=每维 ✅⚠️❓ 覆盖状态，加覆盖率总评与盲区对结论的影响；过程记录归运行日志 |
| 散文里每个数字挂 [公开数据] | 视觉噪音；散文只挂 ✅⚠️❓ 与必要的 [AI 推测]，[来源] 收敛到表格来源列+10.2（§1.8） |
