# 商业可行性分析报告 · 写作方法论（shangyefenxi 子知识库）

> 本文件回答一个问题：**这份报告怎么写——每节写什么、展开到什么颗粒度、怎么保证不同商机输出同样丰满**。
> 10 节框架与排版格式不动（那是 `assets/feasibility_report_template.md` 的地盘），本文件只管"血肉"的深度与形态。
> 整合来源：2026-09-06 实战草案（六种信息形态 + 自问自答环）× 深度调研报告（金字塔原理/MECE/VC 尽调标准/Pre-mortem/ACH/IPBES/红队/JTBD/Lean Startup/SSIR 证据矩阵，见 `references/deep-research-report-writing-methodology.md`）。
> 来源分级：【经典】= 有经典著作或权威机构背书，直接固化；【调研】= 业界调研所得，作启发与判据用；【实战】= 从真实报告对比中归纳。

## 0. 总原则与三层结构

**总原则：宁长勿浅，每个关键判断都值得展开**（hv-analysis 写作精神同款——宁可写长写细，不蜻蜓点水；不为压字数跳过关键判断的展开）。

**篇幅基线：全篇 6000–12000 字（字 = 汉字计数，不含标点、空格与 Markdown 符号）。**
- 低于 6000 → 必有关键判断被蜻蜓点水了，逐节回查补写。
- 超过 12000 → 把枝节推演挪去问答挖掘记录，报告正文只留影响结论的部分。
- 统计口径（机械可判，自检第 0 条用同一条命令）：
  ```bash
  python3 -c "import re;t=open('报告.md',encoding='utf-8').read();print(len(re.findall(r'[一-鿿]',t)))"
  ```
- 靠近上限还是下限，看商机复杂度与资料厚度——关键判断的清单见 §4 定级表（重点节=关键节点，全部适用"值得展开"；定级"薄"的节是非关键节点，说透即可，不硬凑）。

报告每一节内部都是三层，缺层即不合格：

| 层 | 内容 | 服务对象 | 判据 |
|---|---|---|---|
| **L1 导航摘要层** | 每节标题 + 一句话结论 | 扫读者（30 秒/节） | 标题即结论（见 §1.2），不是主题词 |
| **L2 表格索引层** | 关键数据/判断的结构化表格 | 速查者 | 模板已有，每行一断言 + 置信度 + 来源；**单元格限 ≤50 汉字**——论证、机制、推演一律去 L3，表格只留速查级断句 |
| **L3 散文展开层** | 判断链 + 机制解释 + 反直觉点 + 实操模板 | 真正要动手的人 | **本方法论的主要加固对象**，字数基线的主要落点 |

当前报告的常见病：只有 L1+L2，L3 缺失或只有一句"笔者认为"。本方法论的主体就是给 L3 立写作契约。

**三层比例基线（机械可判，按汉字占比不按行数——表格行天然多于散文行，行数比会误伤正常报告）**：成段散文汉字占全文汉字 **≥45%**，表格汉字 ≤40%。统计命令：

```bash
python3 -c "
import re
L=open('报告.md',encoding='utf-8').read().split('\n')
hz=lambda s: len(re.findall(r'[一-鿿]',s))
tot=sum(hz(l) for l in L)
tbl=sum(hz(l) for l in L if l.strip().startswith('|'))
prose=sum(hz(l) for l in L if l.strip() and not l.strip().startswith(('|','#','>','\`\`\`')) and not re.match(r'^\s*[-*] ',l))
print(f'散文汉字 {prose/tot*100:.0f}%（≥45% 合格）| 表格汉字 {tbl/tot*100:.0f}%（≤40% 合格）')"
```

散文汉字占比 <45% 即「表格吞论证」——重点节的分析被塞进了表格长单元格，逐节把长单元格改写为 L3 段落。

## 1. 通用写作规则（每节都适用）

### 1.1 节首 SCQA（【经典】金字塔原理）

每节第一段（L3 开头）按背景（S）→ 冲突/张力（C）→ 核心疑问（Q）→ 本节结论（A）起笔。读者只看每节首段就能拼出全篇逻辑线。不超过 4 句。
**豁免：定级「薄」的第 1 节不强制四段式**（第 1 节的主体是卡片，见 §4），以「结论句 + 缺失项影响」两段替代；定级标准/重点的节必写。

### 1.2 标题即结论（【调研】导航层设计研究）

节标题/小节标题写判断句，不写主题词。不写「客户画像」，写「客户是工程师思维的小老板——谁看得懂图纸就跟谁买」。快速索引表里的「一句话结论」列同理。
**边界消歧（防与模板打架）**：模板的 H3 节标题（「第 N 节 + 主题词」）是编号格式，不受本规则约束。判断句落在三处：①快速索引的一句话结论列；②每节 SCQA 的 A 句；③H4 小节标题（可用判断句，非强制）。

### 1.3 以上统下（【经典】金字塔原理，写后检查）

写完后逐层检查：每个子论点是否指向父论点？每个父论点是否有 ≥2 条支撑？下层不得出现"悬空事实"（不指向任何结论的数据点——发现了要么删掉，要么给它接上结论）。

### 1.4 每节自包含（【调研】专业读者行为研究）

决策者只挑 1-2 节深读。每节结尾加一句「本节对整体结论的影响」：只写"加强了/削弱了/条件化了哪个判断"，**一句话封顶**；与整体结论无实际影响的节允许写「无」，不许为凑格式写绕圈子的正确的废话。

### 1.5 决策请求收尾（【调研】Executive Summary 最佳实践）

3 分钟摘要最后一句必须是决策请求句式：**「建议：[行动]，因为 [核心理由]，前提是 [关键假设]。」** 报告不做 Go/No-Go，但要把"要读者做什么"说清。

### 1.6 判断的姿态（【实战】）

下判断用「我的判断是…」「我倾向于…」这种承认主观性的姿态，先摆事实再给判断，推测必须明说。本技能永远不给"做/不做"的结论，只给依据和建议方向。

### 1.7 读者视角禁则（【实战】首测后增补）

报告写给读者，不是写给流程。以下三类内容禁止出现在交付报告里：

- **过程叙述**：「本定义已去掉空转词」「8 维各补一句」「已做 X 轮检索」这类描述"我是怎么写的"的句子——检查动作留在自检清单，报告只交付检查结果（实质内容或整行删除）。
- **未交付档案的指针**：「见 Q19」「挖掘环 Q6 已证」——读者拿不到挖掘记录/运行日志，一律视为死链。需要引用就把内容内联，或删。
- **技能自指**：「本报告为方法论第 N 个实战样本」这类关于技能自身的元信息——属于开发日志，进 CHANGELOG，不进交付物。

## 2. 六种信息形态（血肉的标准件）

> 适用边界：本节两种模式通用——咨询问答模式的每个回答也按此组织（2-3 种形态/回答）；§1/§4/§5 为报告模式专属。

每个重点节至少覆盖其中 4 种；全篇六种都要有。判据是硬性的——"怎么算做到了"可逐条自查。

| 形态 | 定义 | 怎么算做到了（判据） | 来源与修正 |
|---|---|---|---|
| **① 判断链** | 结论 → 依据 → 机制（为什么成立）→ 边界（何时失效） | 每个核心判断能回答"凭什么"和"什么时候不成立"；且优先展示"什么证据会推翻这个结论"（证伪优先） | 【经典】金字塔以上统下 + ACH 证伪优先。比"结论+置信度"多机制与边界两层 |
| **② 反直觉点** | 与直觉相反但有数据支撑的事实 | 能写出"大多数人以为 X，实际 Y，因为 Z"；且按【调研】证据强度规则：争议度越高的主张证据要求越强，反直觉断言自动触发强证据（≥2 独立来源） | 【经典】CIO 证据强度规则 |
| **③ 对比带弱点** | 每个选项/竞品/打法，优点与代价并陈 | 每个对比项都有"但这招的代价是…"；重大判断升级为 **ACH 竞争性假设**：列 2-3 个竞争性假设（如"可行/有条件可行/不可行"），证据矩阵展示各假设的支持/反对，标置信度 | 【经典】ACH 矩阵（升级自实战版"对比带弱点"） |
| **④ 实操模板** | 读者可直接拿走用的动作级产物 | 话术/邮件结构/checklist/流程步骤，具体到"照着抄"粒度；每篇报告每千字 ≥2 个可操作项（【调研】代理指标） | 【实战】问答记录实证：话术级内容是最被用户认可的部分 |
| **⑤ 验收标准** | 每条建议附"怎么知道做对了" | 能回答：成功阈值是什么数字、失败信号是什么、多久复评 | 【经典】Lean Startup 决策阈值预设 |
| **⑥ 风险推演** | 风险 → 触发条件 → 早期信号 → 应对动作 | 不是"有风险"三个字；"当出现 X 信号时，说明 Y 正在发生，应该 Z"；附"关键信号监测清单"（哪些指标变化会推翻当前结论） | 【经典】Pre-mortem 生成法 + ACH 未来观察标记 |

**置信度纪律（与 SKILL.md 硬底线一致，不另起体系）**：✅/⚠️/❓ 标签照打；低置信断言在 L3 必须展开说明"为什么置信度低、需要什么额外证据"，不许只贴个 ❓ 了事。推演型判断标 ⚠️ 起。

## 3. 自问自答挖掘环（写作前的打料工序，硬环节）

**目的**：报告模式的深度不能只靠初稿一遍过。动笔前，Agent 自己向自己提问并回答，把结论往深处再剥 1-2 层。用户只提 9 问、Agent 自问 10 问的那份问答记录（3.50 号档案）证明此机制有效——本环把它从偶发变成必经工序。

### 3.1 问题从五个出口生成（结构性来源，不靠灵感）

**取问源统一为阶段三的《分析结论草案》**（三要素结论 + 画像一句话 + 张力草案 + 关键缺失项清单，存 `{商机}/跟踪/分析结论草案.md`）。挖掘环在动笔之前运行，初稿报告不存在，不得以报告小节（1.2 / 10.4）为生成源。

| 出口 | 生成源 | 示例 |
|---|---|---|
| **盲区追问** | 分析结论草案的「关键缺失项清单」 | "报价区间缺失会怎样改变第 8 节的验证成本？" |
| **张力对攻** | 分析结论草案的「张力草案」 | "痛点强 vs 信任难——市场上有被验证的解法吗？" |
| **反方质询** | 固定模板（每篇必跑），红队三问 | "什么会让你不批准这个方案？""我们最可能在哪里判断错？""要达到可投决级别还缺什么？" |
| **数字追源** | 关键事实卡片中所有 ⚠️/❓ 条目 | "130 天决策周期对本商机适用吗？怎么验证？" |
| **落地追问** | 阶段三每条建议 | "第一步具体做什么？多少钱？什么标准算做对？" |

### 3.2 Pre-mortem 专项（风险节的生成方法，每篇必跑）

【经典】Gary Klein：假设这个商机一年后已经失败 → 独立写出最可能的 5 个死因 → 按"可预见性×影响度"排序 → 逐条转译为"触发条件+早期信号+应对动作"填入 7.2（模板 7.2 列结构即按此设计）。风险不是罗列出来的，是验尸验出来的。

### 3.3 回答纪律（防自欺）

- **推演型**（只用已有材料推理）：必须展示推理链；推不动就标 ❓"此判断暂缺依据"，不许硬答。
- **挖掘型**（需要新材料）：**必须真的联网检索**再答；检索无结果就写"未见公开数据"并给出用户自验方法（如"联系 3-5 家工厂询价"）——这本身也是可执行答案。
- 所有回答带置信度标签。

### 3.4 预算、落盘与停止条件

- 默认预算 **20 问**（可调），每问允许 1-2 轮纵深追问。
- **问题清单先落盘（硬规则）**：开工第一步把编号问题清单（Q1…Q20，每条标注出口）写入 `问答挖掘记录.md` 顶部；作答按编号逐条追加，断点恢复时按编号跳过已答、从未答处续挖——没有清单不许开答（否则"跳过已答"与预算核对无法机械执行）。
- **整批落盘**：每批 3-5 问（或约每 5 分钟）整批追加落盘一次，取先到；答案含问题 + 推理链/检索结果 + 置信度，一行不落。
- 提前停止：连续 3 个问题的答案不再改变任何结论/建议 → 挖到底了，收手。
- 挖掘记录存 `{编号}_{商机名称}/跟踪/问答挖掘记录.md`，作为报告 L3 的取料库；报告成稿后它不交付给用户（用户只要报告），但保留在商机档案里备查。

## 4. 10 节深度契约（每节：表格层义务 → 展开层义务）

定级原则：定级**重点**的节 = 关键节点，全部适用总原则"宁长勿浅，值得展开"；定级**标准/薄**的节是非关键节点，说透即可，不硬凑灌水。

**重点节 L3 段落契约**：每个重点节的 L3 必须由 **≥3 段连续成段散文**构成——SCQA 首段 + 机制/判断链展开段 + 「本节对整体结论的影响」段；表格层只做速查穿插，不得出现"连续两段以上的论证只存在于表格单元格"的情况。

| 节 | 定级 | L3 展开层义务（表格层照模板） |
|---|---|---|
| 1 项目一句话定义 | 薄 | 卡片 + 资料完整度；L3 只补"缺失项对结论的影响"一段（SCQA 豁免，见 §1.1） |
| 2 市场调研 | 重点 | 每个关键数字跟"so what"（对本商机意味着什么）；趋势判断每条带机制；TAM/SAM/SOM 分层测算（【调研】VC 标准，有可分层数据时）；至少 1 个反直觉点 |
| 3 商业模式拆解 | 标准 | 8 维卡片每维在表格层外补一句"为什么是这个结构"；收入模型按商机阶段调节验证深度（种子期=假设+初步验证，成长期=三角验证【调研】） |
| 4 客户画像 | 重点 | 7 维表格之上必须有：**一句话画像总结**（"他是一个…的人"）+ 流失触发条件清单 + JTBD 任务定义（客户"雇佣"你完成什么任务）+ B2B 补决策链四角色（经济买家/把关者/使用者/执行者；B2C 换购买旅程地图） |
| 5 价值主张 | 标准 | 差异化对比每个竞品带"代价是…"；价值主张用 JTBD 反推（先任务后主张） |
| 6 交付清单 | 标准 | 交付物表格 + 每行补"客户可见/不可见"与复杂度来源 |
| 7 风险评估 | 重点 | 全部风险由 Pre-mortem 生成；每条带机制解释（为什么这个风险在这个模式里必然存在）；风险对称性——每个机会配对下行情景（【调研】Business Case 标准）；附关键信号监测清单 |
| 8 MVP 验证路径 | 重点 | 核心假设按 Lean Startup 四元组重写："我们相信[谁]会[做什么]，因为[原因]；当[指标]在[时间]内变化[幅度]时，我们知道自己是对的"；验证法按三类不确定性分组（需求→技术→商业）；第零步行动必须 30 分钟内可开始 |
| 9 对标对象 | 标准 | 每个对标带"可借鉴/不可借鉴 + 为什么"；链路提炼用箭头流程图（现有做法） |
| 10 决策支撑 | 重点 | 10.2 推断说明强制保留（已有）；10.4 每个张力指向具体 MVP 验证；10.6 每个动作带成本+验收标准；新增关键假设清单（每个假设标来源+敏感度【调研】假设日志化） |

## 5. 丰满度度量与成稿自检

### 5.1 客观度量（写后可数）

- **篇幅基线**：全篇 6000–12000 字，字 = 汉字数（不含标点/空格/Markdown 符号），统计命令见 §0。低于下限逐节回查被蜻蜓点水的关键判断。
- **可操作项密度**：每千字 ≥2 个。**可操作项定义**：以动作动词开头、含具体对象与参数（工具名/数字/阈值）、读者无需再做决策即可照做的条目。正例：「注册 Shopify $27/月店」「首月只投 Bing，预算上限 $1,500」；反例：「做好 SEO」「提升转化率」。写在散文句子中间而非独立条目的，不算。
- **SSIR 证据质量三维度评级**（【调研】Stanford Social Innovation Review）：每个核心断言按 数据/共识/因果链 三维度各评 1-3 级；任何维度 1 级的断言必须补证据或降级为"待验证假设"。
- **散文密度**：成段散文汉字 ≥45%、表格汉字 ≤40%（口径与命令见 §0 比例基线）；重点节各 ≥3 段连续成段散文（§4 段落契约）。
- **形态覆盖**：重点节 ≥4 种信息形态（§2 六选四）。

### 5.2 成稿自检清单（写完逐条过，全部 Yes 才许交付）

> 本清单只管**内容血肉**；**格式**（编号/卡片位置/附录）另按 `assets/feasibility_report_template.md` 末尾「写后格式自检清单」逐项过——两份清单都过才算验收完成。

0. 汉字数落在 6000–12000 吗？（用 §0 的命令数，两种数法口径必须先定；低于下限 → 找出被蜻蜓点水的关键判断并补写，而不是给薄节灌水。）
1. 每节首段是 SCQA 吗（薄节按 §1.1 豁免两段式）？标题/快速索引是结论句吗（按 §1.2 边界）？
2. 每个核心判断有"凭什么"+ "何时失效"吗？反直觉断言有强证据吗？
3. 风险节是 Pre-mortem 验出来的吗？每条带触发条件和早期信号吗（对照模板 7.2 三列非空）？
4. 客户节有一句话画像总结和 JTBD 任务定义吗？
5. 每条建议能拿走就用吗（话术/清单/阈值，按 §5.1 可操作项定义）？每千字可操作项 ≥2 吗？
6. 低置信断言都展开说明"为什么低、缺什么证据"了吗？
7. 有"什么证据会推翻本报告主要结论"的监测清单吗？
8. 3 分钟摘要末句是"建议：[行动]，因为[理由]，前提是[假设]"吗？
9. 每节结尾有"本节对整体结论的影响"吗？
10. 以上统下检查通过吗（无悬空事实）？
11. 交叉一致性校验跑了吗？五组关系逐项过：市场调研 ↔ 风险评估；商业模式 ↔ 行动路线图；客户画像 ↔ 价值主张；交付清单 ↔ MVP 验证成本；对标对象 ↔ 商业模式同赛道。发现矛盾 → 已在 10.4 标注张力并指向 MVP 验证；没跑过不许交付。
12. 散文密度达标吗？用 §0 命令查散文汉字 ≥45%、表格汉字 ≤40%；哪一节把论证塞进了表格长单元格（单元格 >50 汉字）→ 当场改写为 L3 段落再交付。

## 6. 常见错误（来自实战 + 调研）

| 错误 | 纠正 |
|---|---|
| 七维表格填完就走，没有一句话画像 | 画像总结是客户节的灵魂，必须有 |
| 风险是正向罗列的（"可能遇到 A/B/C"） | 用 Pre-mortem 逆向验尸生成，先假设失败；落表时触发条件/早期信号/应对动作三列缺一即不合格 |
| 建议停在"做 LinkedIn 内容"级 | 追到话术/步骤/阈值级（§5.1 可操作项定义） |
| 数字贴完不解释 | 每个关键数字跟"so what" |
| 低置信断言贴个 ❓ 就算交代了 | L3 展开：为什么低、缺什么、怎么补 |
| 自问自答环里自己提舒服的问题、答舒服的案 | 红队三问是固定模板，每篇必跑；挖掘型问题必须真检索 |
| 挖掘环边挖边问、没有编号清单 | 先落盘编号问题清单再作答（§3.4），否则断点续跑与预算核对都无从谈起 |
| 交叉一致性校验被静默略过 | 它是 SOP 独立步骤，已挂入 §5.2 第 11 条，自检清单不过不许交付 |
| 全篇均匀用力 | 按 §4 定级分配笔墨，薄节不硬凑 |
| 全文表格化：表格长单元格塞论证，散文只剩零星"so what"（首测实战病：散文行占比仅 8%） | 表格单元格限 ≤50 汉字；论证、机制、推演一律写成段散文进 L3；用 §0 命令查散文行占比 ≥25% 再交付 |
