# 飞书写入规范

> 所有飞书文档/表格写入操作前必须读取本文件。配合 `feishu_table_fields.md`（15 字段定义）使用。
> 本规范借鉴健身追踪技能 v3.0 的 write-verify 机制，2026-07-30 与用户确认采纳。
> 调用 lark 能力的契约（检测/参数/返回/异常）见 `lark-bridge.md`，遵循《技能桥接模式技术规范》：不直连 API、不持有凭证、失败不自动重试。

## 一、写入通道（三级，按优先级）

| 级别 | 通道 | 检测方式 |
|---|---|---|
| 1（优先） | lark-doc / lark-drive Skill 调用 | 环境中 Skill() 可用性 |
| 2（兜底） | Lark CLI | 本地 `lark` 命令已安装（`command -v lark`）；命令契约运行时以 `lark --help` 自查，凭证由 CLI 自身配置持有 |
| 3（降级） | 手动粘贴 | 生成符合字段要求的内容请用户粘贴，并按错误格式说明原因 |

任一级不可用即下沉一级，不卡死、不静默。**禁止直连飞书开放接口，禁止经手任何飞书凭证。**

## 二、写入顺序

1. **文档轨**：将 10 节报告创建为飞书文档——**创建位置必须是 `config.json` 的 `feishu_folder` 指定的云空间文件夹**（为空则先向用户索取，或本次暂存云空间根目录并提醒用户补配置）→ **回读校验**（检查文档结构完整：标题与各节标题齐全）→ 取得文档链接
2. **表格轨准备**：运行时 `field-list` 实时读取表格实际字段定义（不硬编码字段名）；缺字段则按 `feishu_table_fields.md` 创建 15 个字段
3. **记录定位**：按「商机编号」`record-search` 搜索 → **搜到则更新该行，搜不到则新建一行**（search→upsert）
4. **写入**：A 组 + B 组字段；C 组按红线留空（当前状态默认「调研阶段」）

## 三、写入验证四件套（write-verify）

1. **写后复查**：写入后立即读回，逐字段比对
2. **失败即降级**：复查不一致或写入失败时**不自动重试**（重试由 lark 能力内部负责）→ 按统一错误码输出后降级级别 3
3. **截断检测**：复查时检查返回的字段数量与内容长度，防止长文本被截断
4. **已有值保护**：目标字段已有值时禁止静默覆盖，必须先问用户（C 组决策字段尤其严格）

另：**单选/多选字段写前选项校验**——写入前从 field-list 提取该字段真实选项列表，值必须与已有选项**文本完全一致**（含 emoji），不匹配则停止写入该字段并报 `INVALID_OPTION`。适用字段：商机名称 / 所属赛道 / 当前状态 / 最终决策 / 商机类型。

## 四、统一错误处理

错误输出格式（四行）：

```
[图标] 错误简短描述
原因：具体原因
操作：建议用户执行的操作
影响：该错误对当前流程的影响
```

### 错误码表

| 错误码 | 含义 | 触发场景 |
|---|---|---|
| `CONFIG_MISSING` | 配置缺失 | config.json 缺少 root 或 feishu_table |
| `TABLE_NOT_FOUND` | 表不存在 | feishu_table 链接无法访问 |
| `RECORD_NOT_FOUND` | 记录不存在 | 回填时按商机编号搜不到记录（此时新建） |
| `LARK_UNAVAILABLE` | lark 能力不可用 | lark Skill 与 Lark CLI 均未安装（降级手动粘贴） |
| `FIELD_WRITE_FAILED` | 字段写入失败 | 复查不一致或写入失败（不自动重试，直接降级） |
| `INVALID_OPTION` | 选项无效 | 单选字段值与真实选项不完全一致 |

## 五、决策回填专用规则

咨询问答模式回填字段 9/12/14 时同样遵守本规范：

- 按商机编号 search→upsert 定位记录
- 写前选项校验 + 写后复查
- 字段 13「最终决策」永不代填，仅在用户本人明确说出时按原话记录
- 无凭证时与报告模式同一降级规则（级别 3）
