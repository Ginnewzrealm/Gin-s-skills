# 大纲 JSON 数据契约（v2：三表结构）

生成大纲后，将内容组装为单个 JSON 文件（如 `outline.json`），供 `scripts/feishu_writer.py` 写入飞书。

## 顶层结构

```json
{
  "总纲面板": [ {记录}, ... ],
  "主线与分支线总表": [ {记录}, ... ],
  "剧集总表": [ {记录}, ... ]
}
```

- 键名必须是上述三个中文表名（write 模式要求三表齐全；update 模式可只含待更新的表）。
- 每个记录是对象，键为字段名。未列出的字段名会被拒绝。
- 完整填写示例见 `references/example.json`。

## 各表字段

### 总纲面板（关键字段：项目）
| 字段 | 类型 | 说明 |
|---|---|---|
| 项目 | 文本 | 固定项见下 |
| 内容 | 文本 | 对应内容 |
| 调用产出物 | 文本 | 仅"总攻·××"行填写，引用产出物编号，如 P-01、P-03；其他行留空 |
| 对应集数 | 文本 | 仅"总攻·××"与"黄金三章"行填写，如"第 11–12 集""第 1–3 章"；其他行留空 |

「项目」固定项：
- 基础六项：一句话故事 / 主题内核 / 绝对主线 / 反派对抗目标 / 体量与节奏 / 三线合一触发条件
- 黄金三章：黄金三章·切入点方案一 / 方案二（/ 方案三）/ 黄金三章·选定方案
- 总攻阶段：总攻·集结 / 总攻·突破 / 总攻·决战（/ 总攻·余波）

### 主线与分支线总表（关键字段：编号）
| 字段 | 类型 | 说明 |
|---|---|---|
| 编号 | 文本 | A–E，全局唯一，与剧集总表的「挂载主线」对应 |
| 模块名 | 文本 | 如：情报线 |
| 模块目标 | 文本 | 该线要达成的子目标 |
| 核心人物 | 文本 | 该线主导者，挂接人物卡中的角色 |
| 进度条拉满标志 | 文本 | 可验证的完成条件，如"拿到全部 12 名失踪者档案" |
| 对总攻的贡献 | 文本 | 该线在终局提供什么 |

### 剧集总表（关键字段：任务编号）
每集/每章一行，创作、咬合、产出物流转信息全部在同一行。

| 字段 | 类型 | 说明 |
|---|---|---|
| 集号 | 数字 | 正整数，建议按播出/连载顺序排列 |
| 任务编号 | 文本 | 模块字母+序号，如 A-1、B-3，全局唯一、不复用 |
| 挂载主线 | 单选 | A / B / C / D / E |
| 单元事件 | 文本 | 起因→经过→结果，本单元事件必须闭环 |
| 数据产出 | 文本 | 咬合点：名词级具体的物品/线索（忌"关键线索"式空话），术语与设定名词表一致 |
| 产出物编号 | 文本 | P-01、P-02……全局唯一；每个「数据产出」必须有一个 |
| 消费线 | 文本 | 如"情报线→技术线"（跨线消费是交叉咬合的证据）；本线自耗填单线名 |
| 回收集数 | 数字 | 未回收可留空，但终局前不允许存在未回收产出物 |
| 回收方式 | 文本 | 在哪个场景、以什么方式被使用 |
| 状态更新 | 文本 | 该产出如何推进挂载主线，含进度计数（如"情报线 3/8"） |
| 人物代价 | 文本 | 人物弧光：本单元让主角付出/改变了什么 |
| 结尾钩子 | 文本 | 本单元闭环后抛出的新悬念；必须符合 `references/hook_design.md` 的三维定义（认知缺口/情感赌注/即时反馈）并通过四大检验，废钩黑名单句式禁用 |
| 主线浓度 | 单选 | 低 / 中 / 高；量化锚点见 `references/unit_episode.md` 第三节（低=仅氛围暗示<5%，中=实质推进5–10%，高=剥层节点或认知刷新） |
| 波及主线 | 文本 | 交叉咬合：本单元事件影响到的另一条线；无则留空 |
| 助力还是麻烦 | 单选 | 助力 / 麻烦 / 混合；「波及主线」非空时必填 |
| 反派同步动作 | 文本 | 同一节点反派在推进什么；每 3–4 个单元至少填写一次 |

## 数量规则

- 剧集总表行数 ≈ 总体量 × 单元剧占比；每条分支至少挂载 2 个任务。
- 每个「数据产出」必须有「产出物编号」，且编号在表内唯一。
- 至少 ⌈任务数/4⌉ 行填写「波及主线」（跨线咬合）；「反派同步动作」每 3–4 个单元至少出现一次。
- 总纲面板中"总攻·××"各行引用的产出物编号，必须都能在剧集总表中找到，且终局阶段前全部回收。
- 钩子分层（v2.1）：子钩 1–3 章内兑现；中钩本卷内兑现，卷末跨卷中钩 ≤ 1 个；母钩跨卷悬挂时每 3–4 个单元至少一次强化触击。无「回收集数」的产出物即无反馈窗口钩子，终局前必须清零。
- 剥洋葱与顶针衔接（v2.2）：单元剥层深度与「主线浓度」匹配（常规剥到动机层、"中"剥到结构层一角、"高"刷新人物理解，见 `references/onion_narrative.md`）；相邻单元钩尾钩头衔接，上一单元「结尾钩子」必须有后续单元接钩，无断针。
- 黄金三章（v2.5）：设计前先答 `references/golden_chapters.md` 输入侧七问（读者画像/类型公约须用户确认）；总纲面板"黄金三章·切入点方案"各行须含六项核心目标自评；"选定方案"细化稿须通过该文件第三节审计清单（总量 6000–10000 字、人名 ≤5、含不可逆点）。
- 单元闭环与递进（v2.4）：每单元满足闭环四必须（独立戏剧问题/情感闭环/代价/余韵）；赌注逐单元递增；每单元主线推进 ≥5%；连续高浓度单元 ≤2 个后必有喘息单元。详见 `references/unit_episode.md`。
