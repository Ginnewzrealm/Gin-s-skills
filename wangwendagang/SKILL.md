# 嵌套剧本架构师（OpenClaw 版 v2.5.0）

将用户的设定素材组织为三层嵌套大纲，反推黄金三章切入点，并落地为飞书多维表格中的**三张表**。严格按以下阶段执行。

依赖：python3 + requests（脚本执行前若缺 requests，先 `pip install requests` 或 `uv pip install requests`）。

> **四大强制知识库（v2.1–2.4，全程引用）**：
> 1. **钩子与悬念** `references/hook_design.md`：一切钩子（结尾钩/卷末钩/总攻钩/黄金三章钩）的三维定义与四大检验。
> 2. **剥洋葱叙事** `references/onion_narrative.md`：真相四层模型、顶针式钩尾衔接、延迟解码。
> 3. **黄金三章** `references/golden_chapters.md`：输入侧七问（读者画像/类型公约/人物锚点/冲突引擎/信息管控/情绪曲线/结构骨架）+ 输出侧"钩子/磁铁/炸弹"三章分工 + 审计清单。
> 4. **单元剧设计** `references/unit_episode.md`：闭环四必须、递进原则、主线投放量化、串联机制五型、节奏曲线。
>
> 分工：钩子质量查 1，真相层次与衔接查 2，开篇三章查 3，单元闭环与全书节奏查 4。设计前先查阅，设计后逐项对照审计；Fail 项重写，禁止带病进入下一阶段。

技能被调用的整个过程中，必须持续向用户输出可见反馈，让用户随时知道"技能正在工作、工作到哪一步"。反馈三种类型：

```
📚 知识库待命：hook_design / onion_narrative / golden_chapters / unit_episode（设计到对应环节时查阅，查阅后亮 🔍 徽章）
🗺 流程：阶段0 素材体检 → 阶段1 架构生成 → 阶段2 黄金三章 → 阶段3 JSON组装 → 阶段4 飞书写入 → 阶段5 交付
📍 当前：阶段0 · 素材收集与逻辑体检
```

### 2. 阶段切换反馈（每进入/完成一个阶段，各输出一行）

- 进入：`▶️ 进入阶段N · {阶段名}`
- 完成：`✅ 阶段N 完成 · {一句话成果}`，并附流程进度条，如：

### 3. 质检徽章（每次执行强制查阅/审计后，必须亮出结果）

## 阶段 0：素材收集与逻辑体检

### 0.1 收集输入

素材**形式随意**（散句、文档、聊天记录均可），核心五类：

| 输入 | 说明 |
|---|---|
| 世界观 / 背景设定 | 世界运行规则、力量体系、"普通人是否知情"等基石 |
| 人物角色卡 | 主角、反派、关键配角的身份、动机、关系 |
| 世界重大事件 | 编年史式的大事记，是主线的骨架素材 |
| 设定名词表 | 专有名词、术语、物品名，保证全书称谓一致 |
| 体量与基调 | 网文（总章节数 × 单章字数）/ 短剧 / 网剧；基调类型；分支线数量（默认 3 条，2–5 条）；单元剧占比（默认 7:3） |
| 读者画像与类型公约（v2.5） | 目标读者（年龄/阅读经验/阅读场景/心理预期/劝退点）与赛道类型公约（类型期待/开局禁忌/3–5 本标杆书）。可缺省：缺省时按类型默认值处理，标注"待确认"，阶段 2 前须补齐或确认 |

素材不全不阻塞：缺哪类，依据已有素材补齐草案，并在审校报告中标注"待用户确认"。

### 0.2 逻辑体检（必须执行）

对全部素材做严密性审查，输出**审校报告**，逐项列出：

- **逻辑漏洞**：因果断裂、动机不成立、规则自相矛盾（如力量体系上限被某事件突破）；
- **重复冲突**：同一设定出现两个版本、人物卡之间关系矛盾、名词同物异名 / 同名异物；
- **不合理之处**：时间线对不上、重大事件的影响与后续设定脱节、伏笔无处可去。

每条问题给出：位置、问题描述、修正建议（2 个以内，附倾向推荐）。
**未经用户对审校报告确认（采纳或驳回修正），不得进入阶段 1。**

## 阶段 1：架构生成（四步）

### 步骤一：确立绝对主线
- 提炼贯穿始终的终极目标，写出一句话故事与主题内核。
- **必须同时设计反派对抗目标**：反派有自己的"终极目标"和进度条，与主角构成双向博弈。

### 步骤二：拆解分支主线
- 按"达成终极目标所需的不可替代能力域"拆分（如情报/技术/人脉），2–5 条，默认 3 条。
- 每条线给出：模块名、目标、核心人物（直接挂接人物卡中的角色）、可验证的进度条拉满标志、对总攻的贡献。

### 步骤三：设计单元剧
按以下规则逐集/逐章设计，行数 ≈ 总体量 × 单元剧占比，每条分支至少挂载 2 个任务。**开始前先声明串联机制选型**（unit_episode.md 第四节五型，默认事件链，可主辅搭配）。
- **六要素齐全**：单元事件（起因→经过→结果，本单元闭环，按 unit_episode.md 第六节简化三幕展开）、数据产出（咬合点）、状态更新（含进度计数）、人物代价（弧光）、结尾钩子、主线浓度（低/中/高）。
- **闭环四必须（v2.4）**：每个单元过 unit_episode.md 第一节门槛——独立戏剧问题本单元提问本单元回答、情感闭环、代价、余韵；事件闭环但情感或主线留口子，禁止"太干净"。
- **递进与投放（v2.4）**：难度递进（赌注逐单元增大，禁平铺）；成长三账（能力/情感/认知）每单元至少变动一本；每单元主线推进 ≥5%（非番外），主线浓度按 unit_episode.md 第三节量化锚点定档。
- **闭环与钩子并存**：本单元事件必须有结果，同时从主线层面抛出新悬念。
- **钩子强制质检（v2.1）**：设计每个「结尾钩子」时，必须先查阅 `{baseDir}/references/hook_design.md`，按三维定义（认知缺口/情感赌注/即时反馈）立意，再逐条过四大检验（刺痛神经/绑定核心欲望/可操作线索/母子钩子分层）；任一检验 Fail 当场重写。每个钩子必须能回答：它是子钩还是母钩？子钩闭合时拧紧了哪个母钩？反馈窗口是几章？废钩黑名单（hook_design.md 第六节）中的句式一律禁用。
- **名词级具体**：产出物写"一枚刻着真实坐标的怀表"，禁止"关键线索""重要信息"式空话；产出物与术语必须与设定名词表一致。
- **任务编号**：模块字母 + 序号（A-1、B-3），全局唯一，一经使用永不复用。

### 步骤四：设计咬合与总攻
- **交叉咬合**：至少 ⌈任务数/4⌉ 处——某条线的产出被另一条线消费（填"消费线"），或某线行动给另一线制造麻烦（填"波及主线 + 助力还是麻烦"）。
- **反派同步**：每 3–4 个单元至少一行填写"反派同步动作"；该列同时承担母钩强化职责（反派每推进一步，母钩拧紧一格）。
- **母子钩子分层（v2.1）**：全书钩子按 hook_design.md 分层管理——子钩 1–3 章内兑现、中钩本卷内兑现（卷末跨卷中钩 ≤ 1 个）、母钩跨卷悬挂期间每 3–4 个单元至少一次强化触击（新信息/新威胁/新代价），禁止静默悬挂。产出物的「回收集数」即反馈窗口承诺，终局前不允许存在无窗口的产出物。
- **剥洋葱结构（v2.2）**：单元解谜与主线真相按 onion_narrative.md 四层模型（现象/动机/结构/根源）分配——常规单元剥到动机层，浓度"中"剥到结构层一角，浓度"高"必须刷新读者对某人物的理解；绝对主线四层完整分布（现象开篇、动机前半程、结构中点、根源终局）。相邻单元执行顶针式衔接：上一单元的钩尾必须是下一单元的钩头，无"断针"；每单元至少排除一种错误可能性。
- **节奏曲线（v2.4）**：全书单元按 unit_episode.md 第五节排布情绪波浪线——大小单元交替、连续高强度 ≤ 2 个（之后必有喘息单元）、赌注只增不减；设计完用一条曲线快照自检防"平"。
- **三线合一总攻**：分阶段（如集结/突破/决战/余波），每阶段引用具体产出物编号；终局前不允许存在未回收的产出物。

## 阶段 2：黄金三章切入点（先出候选，再生成）

> **质量标准（v2.5 强制）**：本阶段全程对照 `{baseDir}/references/golden_chapters.md`——先答输入侧七问（读者画像/类型公约/人物锚点/冲突引擎/信息管控/情绪曲线/结构骨架），再按输出侧"钩子/磁铁/炸弹"规格装配，最后过审计清单。

1. **七问核对（v2.5 前置步骤）**：逐问作答 golden_chapters.md 第一节七问。问 1（读者画像）、问 2（类型公约）若阶段 0 未收集，先向用户补问或按类型默认值标注"待确认"；七问未答清不得生成候选方案。
2. 基于阶段 1 的完整剧情与七问答案，反推**黄金三章最佳切入点**，给出 **2–3 个候选方案**，每个方案包含：
   - 切入点事件（从哪个场景/冲突开书）；
   - **六项核心目标自评**（v2.2）：逐项一句话说明该切入点如何达成冲突前置/明确目标/代入感/紧迫感/能力展示/章末钩子，答不上来的项标红；
   - 推荐理由（为什么最抓人：悬念强度、主角魅力展示、世界观抛出的自然度）；
   - 代价提示（该切入点放弃了什么铺垫，需要在后文第几章、以什么方式回补——回补必须顶针衔接进既有悬念链，不得另起炉灶）。
3. 向用户陈述候选方案，**等用户选定**后，将选定方案写入总纲面板（"黄金三章·选定方案"行），候选方案一并保留备查。
4. 用户要求时，按选定切入点细化前三章逐章内容（总量 6000–10000 字，人名 ≤5）：
   - 第一章按"钩子"规格：开篇首句用动作或反常画面、前 1000 字启动冲突、500 字内出变故、冲突公式（危机+反常+代价）、"非常态反应"立人设、禁堆设定禁回忆杀；
   - 第二章按"磁铁"规格：解决阶段性困境展能力、冰山法则藏九露一、悬念链顶针递进、结尾第一个反转；
   - 第三章按"炸弹"规格：冲突升级到"不翻第四章睡不着"的临界点、中后段放不可逆点、认知颠覆或双重困境、前三章最强章末钩；
   - 三章章末钩子全部过 hook_design.md 四大检验，细化稿交付前过 golden_chapters.md 第三节审计清单（含量化红线与外部视角 8 问），Fail 重写。

## 阶段 3：组装大纲 JSON

1. 阅读 `{baseDir}/references/data_format.md` 的数据契约（三表字段、类型、数量规则）。
2. 参考 `{baseDir}/references/example.json` 的写法与具体度。
3. 将三表内容写入一个 JSON 文件（如 `outline.json`）。
4. 写入飞书前先离线校验：
   `python3 {baseDir}/scripts/feishu_writer.py self-test --data outline.json`
   校验报错时修复 JSON 后重试，不要绕过校验直接写入。
5. **质量审计关卡（与 self-test 并列强制，一次过堂四项）**：任何一项 Fail，修复后重审；全部 Pass 才允许进入阶段 4。审计结果以简表留存（任务编号 / 审计项 / 判定）。
   - **钩子审计**（hook_design.md 第四节）：剧集总表全部「结尾钩子」逐行过四大检验＋三维复查＋子母钩归属＋反馈窗口，抽查总攻钩与卷末钩；
   - **剥洋葱审计**（onion_narrative.md 第五节）：剥层深度与浓度档位匹配、钩尾钩头无断针、排除法推进、主线四层节奏分布、根源层落到人；
   - **单元审计**（unit_episode.md 第七节）：闭环四必须、递进与成长三账、主线投放 ≥5%、节奏张弛；
   - **黄金三章审计**（golden_chapters.md 第三节）：仅当本次细化了前三章时追加。

## 阶段 4：写入飞书多维表格

1. 检查同名表冲突：
   `python3 {baseDir}/scripts/feishu_writer.py list-tables --base-url <链接>`
2. 若已存在同名表（0-总纲面板 等），**先询问用户**：覆盖重建（overwrite）、新建带时间戳副本（rename）、还是取消。得到明确同意前不要覆盖。
3. 写入：
   `python3 {baseDir}/scripts/feishu_writer.py write --base-url <链接> --data outline.json --on-conflict <策略>`
4. 报错时按脚本输出的排查提示处理；常见原因见"排错指南"。

## 阶段 5：交付

向用户返回：
- 三张表各自的行数与飞书链接。
- 文本进度条快照，如：`情报线 ███░░░░░ 3/8　技术线 ██░░░░ 2/6　人脉线 █░░░░░ 1/6`。
- **悬念分层表（v2.1）**：列出全部母钩（内容 / 起始集数 / 反馈窗口 / 强化触击节奏）与子钩数量统计，并附钩子审计结果（Pass 总数、修复记录）。
- **真相分层图（v2.2）**：绝对主线的四层（现象/动机/结构/根源）各自在哪几个单元揭开，标注每次"刷新人物理解"的剥层节点。若已细化黄金三章，附三章分工与审计结论。
- **节奏曲线快照（v2.4）**：全书单元的情绪强度波浪线（标注大/小/喘息单元），并附串联机制选型说明。
- 黄金三章选定方案的一句话摘要。
- 本次采用的默认参数（若有）。
- 提醒用户剧集总表的"产出物编号 / 消费线 / 回收集数 / 回收方式"四列可用于后续写作对账：每个伏笔从哪来、到哪去、第几集回收。

## 迭代协议（用户要求修改时）

- **局部修改**：只重新生成受影响的内容，组装为只含相关表的 JSON，用 update 模式按编号 upsert：
  `python3 {baseDir}/scripts/feishu_writer.py update --base-url <链接> --data partial.json`
- **保持编号稳定**：任务编号、产出物编号一经确定不复用、不重排；删除任务时在结果中说明其下游影响。
- **波及检查**：修改某条支线后，检查剧集总表中引用该线产出物的记录（消费线、回收方式）是否同步更新。
- **素材变更**：若用户修改了世界观/人物卡等底层素材，先重跑阶段 0.2 的逻辑体检，再评估受影响的表。

## 飞书接入引导（提供给首次使用的用户）

1. 打开飞书开放平台（open.feishu.cn），创建「企业自建应用」。
2. 在「权限管理」中开通多维表格（Bitable）相关读写权限，创建版本并发布。
3. 打开目标多维表格，通过 右上角「…」→「更多」→「添加文档应用」 将该应用添加为协作者（否则写入会报权限错误）。
4. 获取 app_id 与 app_secret，按下节配置到 OpenClaw，或在对话中临时提供。

## OpenClaw 配置

在 `~/.openclaw/openclaw.json` 中为本技能注入凭证（推荐，避免每次对话传递）：

```json
{
  "skills": {
    "entries": {
      "wangwendagang-v2-5-0": {
        "env": {
          "FEISHU_APP_ID": "cli_xxxxxxxx",
          "FEISHU_APP_SECRET": "xxxxxxxx"
        }
      }
    }
  }
}
```

常用命令：

```bash
openclaw skills list --eligible      # 确认技能已加载且依赖检查通过
openclaw skills info wangwendagang-v2-5-0   # 查看 metadata 与依赖声明
openclaw gateway restart             # 修改技能或配置后重启生效（或会话内 /new）
```

## 排错指南

| 症状 | 原因与处理 |
|---|---|
| 技能未出现在 skills list | python3 缺失（requires.bins 拦截）；或放置目录不对、未重启 gateway |
| 获取 token 失败 | app_id/app_secret 错误，或应用未启用未发布 |
| 权限不足 / 403 | 应用未被添加为该多维表格协作者；或未开通多维表格权限、权限未随版本发布 |
| 无法解析链接 | 用户提供的是电子表格（/sheets/）或文档（/docx/）链接，引导其新建「多维表格」并复制 /base/ 链接 |
| 校验报错（未知字段/非法单选值） | JSON 不符合契约，对照 {baseDir}/references/data_format.md 修复 |
| 同名表冲突 | 按阶段 4 第 2 步询问用户后选择策略 |
