# 技能深挖手册（Skill Mining Playbook）

> 触发：为核心技能写详细描述（岗位胜任 / 技能详情 / 面试素材）前，信息不足时必读。
> 核心原则：**把创作题变成选择题、填空题、改错题。** AI 只提问与改写，事实必须用户亲口提供；挖完走确认门禁（见 skills-inventory-standard.md）。
> 铁律：不抛开放式大问题、一次只问一个点、不替用户编事实。

## 一、挖掘分层（先判断挖多深）

| 层级 | 对象 | 挖掘深度 |
|------|------|---------|
| 核心技能 | 与目标 JD 强相关、每组 1-2 个 | 挖全五维（情境/行动/结果/沉淀/反事实） |
| 其余技能 | 清单里的其他条目 | 维持 skills.md 一行佐证，不挖 |

判断依据：JD 分析的高频要求 + 用户求职意向。不要全量深挖——20 条技能每条挖五维会把用户问跑。

## 二、支架式提问四手段

**1. 选择题化**——能列选项的绝不让用户裸答：
> ❌ 当时业务什么情况？
> ✅ 你接手时，大区业绩处于哪种状态？A 下滑 B 停滞 C 增长但增速放缓 D 新开拓

**2. 填空式拆解**——把大问题拆成张口就来的小事实（数字/人数/时间/工具名）：
> ❌ 讲讲你的谈判方法论
> ✅ 团队当时几个人？里面几个新人？你谈判前做的第一件事是什么？

**3. 示例锚定**——给一个同岗位样板答案，让用户照着说或直接改：
> 销售岗通常这样描述：「接手时区域连续两季度下滑 15%，团队 8 人里 3 个新人」——你的情况对照着是什么样？

**4. 草稿纠偏（底牌）**——用户答得零碎没关系，AI 把碎片拼成完整描述，让用户**改**而不是**写**：
> 我先根据你说的拼一版：「……」——哪里不对、漏了什么，直接在上面改。

人改一段话的成本只有写的十分之一，改的过程本身就会唤起新信息。

## 三、挖掘漏斗（顺序不可颠倒）

1. **硬事实层**（零压力，先问）：数字、人数、时间、工具名称
2. **行动决策层**（中难度，配示例锚定）：第一步做了什么、用了什么工具/方法、为什么这么做、有没有别的方案
3. **沉淀抽象层**（最难，**AI 提炼 → 用户确认**，绝不让用户自己总结）：
   > 我帮你提炼一下可复用的方法：「谈判前先解决对方库存焦虑，再谈增量」——这么说准吗？
4. **反事实验证**（校验器）：换一个运气不好但方法相同的人，大概率能达成类似结果吗？
   - 能 → 挖到了「能力」，通过
   - 不能 / 用户说不清 → 描述还停留在「经历」层，回到行动层补行为模式

## 四、五维问题库（STAR-Plus）

### S/T 情境（挖变量、压力、业务痛点）
- 选择：你接手时业务/团队处于什么状态？（下滑 / 停滞 / 增长放缓 / 新开拓）
- 填空：团队几人？几个新人？预算或时间上的硬约束是什么？
- 锚定：「××岗通常这样说：接手时……」——你对照着讲

### A 行动（挖工具、动作、决策逻辑）
- 填空：你做的第一件事是什么？用了什么工具/方法/模型？
- 追问：当时有没有别的方案？为什么选这个？（决策逻辑是区分「做过」和「会做」的关键）

### R 结果（挖量化指标与可验证产出）
- 填空：前后对比的数字？用了多久？谁验证或认可了这个结果？

### Plus 沉淀（AI 提炼，用户确认）
- 标准话术：「我帮你提炼一下：……（可迁移的方法/SOP），这样概括准吗？」
- 硬技能侧重「产出物与技术指标」；软技能侧重「行为模式与跨场景复用性」

### 反事实（成稿前必过）
- 结果里有多少是行情/平台/运气的成分？方法换成别人用还成立吗？

## 五、完整对话范例（销售岗 · 核心技能「商务谈判」）

> **AI**（选择+填空）：先问几个硬的：你主导那次省级经销商签约时，团队几个人？你接手时大区业绩是下滑、停滞还是增长？
> **用户**：8 个人，业绩在下滑。
> **AI**（锚定）：销售岗一般这样讲：「连续两季度下滑 15%，经销商标配库存积压」——你当时下滑多少？经销商那边最大的抱怨是什么？
> **用户**：差不多 15%。他们主要是库存压着不想进货。
> **AI**（决策逻辑）：你做的第一件事是什么？是直接谈进货量，还是先处理库存？
> **用户**：先帮他们清库存，做了个动销活动，然后才谈的新合同。
> **AI**（结果）：从清库存到签约用了多久？合同金额多少？
> **用户**：三个多月，两家省代，一笔 3000 万。
> **AI**（沉淀，AI 提炼）：我提炼一下你的方法：「谈判前先解决对方的库存焦虑，再谈增量」——准吗？
> **用户**：对，差不多就是这个意思。
> **AI**（反事实）：这个方法换个行业、换个客户还能用吗？
> **用户**：存量客户都行，先解决对方的包袱再谈条件。
> **AI**（草稿纠偏）：我拼好了，你看哪里要改：

```
## 商务谈判
- 情境：接手时区域连续两季度下滑 15%，经销商库存积压、进货意愿低
- 行动：先做动销活动帮经销商清库存，再以「阶梯返利」框架主导合同谈判
- 结果：3 个多月主导 2 家省级经销商签约，单笔 3000 万
- 沉淀：谈判前先解决对方的包袱，再谈增量——可复用于一切存量客户谈判
```

> **用户**确认 → 写入 `原始事实/skill_details.md`。

## 六、通用能力发现模式（与技能详情深挖的分工）

技能详情深挖（第一~五章）面向**已知技能补详情**；本章面向**通用能力的发现与验证**（沟通/协作/适应性/批判性思维/情绪智力/项目管理/数字敏度等）。

### 与支架式深挖的分工

| | 技能详情深挖（支架式） | 通用能力发现（行为面试式） |
|---|---|---|
| 对象 | 用户已点名的专属能力 | 散落在经历里、用户自己没意识到的通用能力 |
| 起点 | 技能名已知，缺细节 | 能力未知，要从场景里还原行为模式 |
| 问法 | 选择题/填空题/改错题 | 开放式行为问题 + STAR 追问（同样配示例锚定） |

### 操作流程

1. **开放式行为问题切入**（配示例锚定，不空问）：
   > 你上次需要协调多方利益、但各方有冲突，是什么情况？（比如跨部门争预算、跟难搞的客户续约这类场景）
2. **STAR 追问细节**：情境 → 任务 → 你具体做了什么、怎么说的 → 结果如何、学到什么。层层剥「具体怎么做的」，不收笼统结论
3. **追问 3+ 个不同场景**：一个例子不构成模式，3 个以上不同情境的完整 STAR 才构成能力证据
4. **证据强度评级**（写进条目，见 skills-inventory-standard.md）：
   - 强 = 3+ 个不同场景完整 STAR；中 = 1-2 个完整 STAR
   - 弱（讲不清细节）/ 不可信（只有主观结论）→ 不入库，回炉再挖或放弃
5. **可选增强——多来源交叉**：自己说 + 同事/客户/下属独立反馈一致 = 可信度最高；只有自说自话不判「强」
6. **情境模拟**：通用能力亦可出模拟场景题考察（「假如经销商当场拒绝压货，你怎么回应」）——此招同时是面试准备的素材，可衔接 N12 面试清单

### 铁律（本章同样适用）

- 严禁直接问「你沟通能力怎么样」——对方怎么回答都没有证明效力
- 通用能力条目必须带场景（fact_id + 一句话行为），确认门禁与专属能力相同
- 「做成过 = 会做」「证书 = 能力」「别人说我强 = 我强」都是误区，验证看行为过程与情境一致性

## 七、成稿词汇与句式规范（改写时执行）

- **禁用词**：负责、参与、协助、精通、良好、丰富经验
- **强制词**：主导、重构、优化、构建、推动、设计、实现
- **句式公式**：强动词 + 策略/工具 + 量化结果
- **领域适配**：硬技能重产出物与技术指标；软技能重行为模式与跨场景复用；商业/市场岗强制商业语言（CAC、LTV、ROI、CVR），强调投入产出比
- 与 `writing-formulas.md` 的 X-Y-Z 公式同源，详细描述按本手册 STAR-Plus，单行 bullet 按 X-Y-Z

## 八、落盘

- 确认后的五维块写入 `原始事实/skill_details.md`（格式见上），随后运行 `facts_parser.py` 重建 facts.yaml
- skill_details.md 与 skills.md 分工：清单层（skills.md）一行条目管 ATS 与注册；详情层（skill_details.md）五维块管详细描述生成
- 挖掘成果同时是面试 STAR 故事的素材，生成 STAR 故事库时优先复用
