# 输出契约

## 唯一事实源

`model.json` 是流程事实的唯一来源。Markdown、HTML 和问题单均由 `scripts/process_model.py` 生成。需要修改输出时，先改 JSON，再重新生成；不要在生成文件中单独修补条件或编号。

## Markdown 流程说明

必须包含：

1. 公司、流程名称、状态、决策数、待确认数。
2. 从起点到所有终态/待确认终点的纯文字决策树。
3. 每个 `Dxx` 的决策人、判断信息、判断标准、证据状态、分支条件和去向。
4. 完整待确认问题。
5. 图例、资料来源和“不补造企业事实”声明。

## HTML 决策路径图

必须满足：

- 单文件、离线可打开，不加载外部脚本、字体或样式。
- 中央纵向主线保持清晰；其他分支靠右显示，不用角色泳道占据主要视觉空间。
- 颜色固定：蓝色动作、黄色决策、红色其他/待确认分支、绿色终态。
- 决策卡直接展示判断信息、判断标准、分支条件和目标，不要求读者来回跳转。
- 长文字自动换行；窄屏改为单列；打印时不依赖背景页面。

## 待确认问题单

按影响决策路径的优先级排序。每个问题应具体到阈值、责任人、条件组合、否决去向或完成标准，避免“请补充更多信息”这类泛问。

## 一致性检查

- Markdown 和 HTML 中的 `Dxx` 集合相同。
- 同一个分支在两种输出里的 `condition` 和 `target` 相同。
- `pending_questions` 数量与两种输出显示的数量相同。
- 输出状态为“已确认”时，严格校验必须通过。
