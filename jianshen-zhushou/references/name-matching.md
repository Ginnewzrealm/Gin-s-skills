# 动作名称匹配规则（同名判定真源）

> 何时读我：① 场景四入库时判断「该动作在索引中是否已存在」；② 训练日记回流时，把训记/外部来源的动作名映射到索引动作；③ 索引巡检查重时，判定索引内两行是否同一动作（比对范围从「新动作 vs 索引」变为索引内部互比，规则见 kb-structure.md「查重标记」）。遇这三种情况必须先读本文件，禁止凭字面相似度直接判定。

## 1. 基准端与匹配目标

- **基准索引 = 用户的动作索引.md**（唯一匹配目标）：判断任意输入名称 ↔ 索引中某一行 = 同一个动作
- 训记动作库清单等外部清单仅作命名参考，不作为匹配目标
- 匹配结论只有三种：**已存在**（指向唯一索引行）/ **不存在**（入库走新建、回流提示补录）/ **不确定**（列出候选请用户确认）——不确定时禁止猜

## 2. 匹配四原则（冲突时按此优先级）

### 原则一：动作本质优先

匹配依据是生物力学模式和主要发力肌群，不是名称字面相似度。名称只是标签，轨迹才是本质。

- 正例："拉力器下压"≈"绳索三头下压"——同为肘关节伸展、三头肌主导 → 可匹配
- 反例："哑铃侧平举"与"哑铃前平举"名称相似，但运动平面（冠状面 vs 矢状面）和目标肌束（中束 vs 前束）完全不同 → 严禁匹配

### 原则二：目标肌群一致

输入与索引动作的主要目标肌群必须一致；名称未写肌群时通过核心词推断，推断结果不符 → 直接排除。

- 反例："杠铃划船"（背）与"杠铃弯举"（二头）同用杠铃 → 严禁匹配

### 原则三：器械/阻力类型一致

阻力来源（自由重量/固定器械/绳索/自重/弹力带）必须同类。不同阻力类型的轨迹和阻力曲线差异大，不可混用。

- 反例："杠铃卧推"（自由重量）与"器械推胸"（固定器械）→ 严禁直接匹配

### 原则四：轨迹与方向一致

运动平面（矢状面/冠状面/水平面）和关节运动方向（推/拉/屈/伸/旋转）必须一致。

- 反例："俯身飞鸟"（水平外展）与"俯身侧平举"（冠状面外展）姿势相似但平面不同 → 严禁匹配

## 3. 匹配流程（五步）

**第一步：清洗**
去除空格、特殊符号、无意义前后缀（"动作：""练习"）、营销修饰词（"10分钟""暴汗""速成""虐腹"）；错别字容错修正（如"俯卧陈"→"俯卧撑"），但修正过的输入匹配置信度降一档，结论中说明。

**第二步：标准化**
把名称拆成五个成分：器械 / 姿势 / 握法 / 动作核心词 / 变体修饰，按第 5 节映射表把别名翻成标准词。

**第三步：检索**
用「核心词 + 器械 + 姿势」在动作索引.md 中找候选；输入含部位信息时，先定位到对应部位一级标题再检索。命中层级：

- 完全匹配：所有成分一致 → 直接用
- 高度匹配：核心词+器械一致，姿势/握法为默认 → 直接用
- 部分匹配：核心词一致，器械/姿势有变体 → 必须过第 4 节验证清单
- 仅语义相似（如"下拉"与"引体向上"）→ 只作候选，须用户确认

**第四步：选候选**
多个候选时用排除法逐一排除不匹配的，不只看像不像；平局时优先基础版（无版本/变体标注），其次变体最简者。

**第五步：验证**
过第 4 节验证清单：全部通过 → 输出；任一关键项未通过 → 换次优候选重新验证；仍不通过 → 走第 6 节边界处理。

## 4. 验证清单（输出前必须逐项过）

| 检查项 | 通过标准 | 未通过处理 |
|--------|----------|-----------|
| 核心词 | 标准化后与索引动作一致或为公认同义 | 排除该候选 |
| 目标肌群 | 主要目标肌群一致 | 排除该候选 |
| 器械类型 | 器械二级分类一致 | 排除该候选 |
| 运动方向 | 推/拉/屈/伸方向与运动平面一致 | 排除该候选 |
| 姿势角度 | 上斜/下斜/平板/站姿/坐姿等一致 | 降级为「相关动作」，不算匹配 |
| 握法 | 宽/窄/对/反一致或为默认握法 | 降级为「相关动作」，不算匹配 |
| 变体兼容 | 输入无变体→匹配基础版；有变体→匹配对应变体 | 匹配基础版并说明「变体可能不同」 |
| 索引唯一性 | 一个输入只对应一个索引行 | 有歧义 → 列出所有候选请用户确认 |

**反向验证（收尾必做）**：把匹配到的索引动作名用大白话描述一遍，看和输入说的是不是同一个动作；说不通 → 回到候选集重选。

## 5. 同义词映射表（标准化依据）

### 器械别名（对齐索引 12 类二级标题）

| 别名 | 归位 |
|------|------|
| 拉力器、钢线 | 绳索/龙门架 |
| 史密斯 | 史密斯机 |
| 悍马 | 悍马机 |
| 蝴蝶机、腿举机、挂片器械、健身机 | 固定器械 |
| T 杠 | 地雷杆 |
| 徒手、俯卧撑架、双杠 | 自重 |
| 吊索、TRX | 悬挂 |
| 杠铃片负重 | 杠铃 |

**注意：弹力带、弹力绳、壶铃在本体系是独立器械二级，禁止并入绳索。** 索引无对应器械二级时（如健身球）→ 按动作本质归最近类，或问用户。

### 姿势/角度别名

平板=平躺=仰卧；上斜/下斜/站姿/坐姿/跪姿/俯卧 原样使用。

### 握法别名

宽握=宽距；窄握=窄距；掌心向内=对握；反握=反手；正握=正手；锤式握法=锤式。

### 动作核心词别名

**只用于找到候选，最终仍须过验证清单；索引里的实际名称不改。**

俯卧撑=卧撑；后弓步=后退弓步=箭步蹲；驴踢=后蹬=后踢；肩推=推肩=推举；蝴蝶机=夹胸。

**差异提醒（不许合并）：** 仰卧起坐 ≠ 卷腹（髋部参与不同）；臀桥 ≠ 臀冲（支撑点不同）——名称相近但本质有别的，按两个动作处理。

### 输入来源特征（预判命名风格）

| 来源 | 特征 | 应对 |
|------|------|------|
| 健身 App | 较规范，有品牌术语 | 按映射表转标准词 |
| 视频平台 | 口语化、营销修饰多 | 先去修饰词再提取核心动作 |
| 教练口述/语音 | 方言、口误、简称 | 结合上下文推断 |
| 外文翻译 | 同义异形多 | 按动作本质匹配（如 Lat Pulldown=高位下拉） |
| 用户口语 | 极简、模糊、错别字 | 容错处理，置信度降档并说明 |

## 6. 边界情况

1. **无匹配**：入库场景 → 按新动作建档；回流场景 → 提示"库里没这个动作，要补录吗"，禁止把数据挂到别的动作上
2. **多候选**：列出候选请用户选，禁止擅自决定
3. **极简模糊名**（如"深蹲"）：索引里只有一个对应变体 → 直接用；有多个 → 列出请用户选
4. **复合动作**（如"深蹲推举"）：先查索引有无精确项；无 → 建议拆分为"深蹲 + 推举"分别匹配/建档
5. **全新动作**：索引中完全不存在且无合理映射 → 入库走新建流程，回流提示补录

## 7. 找对 vs 找错（对照案例）

| 输入 | 错误匹配 | 错因 | 正确处理 |
|------|----------|------|----------|
| 拉力器宽握下拉 | 绳索下拉 | 丢失握法特征 | 索引中找「绳索+宽距+下拉」对应行 |
| 哑铃侧平举 | 哑铃前平举 | 运动平面不同 | 哑铃侧平举 |
| 杠铃划船 | 杠铃弯举 | 目标肌群不同 | 无匹配，不排除为误输 |
| 弹力带交替胸前推 | 器械推胸 | 器械不同类 | 无匹配，列相近候选请用户确认 |
| 高位下拉（视频标题"练背神器"） | 直接去标题找 | 营销词干扰 | 清洗后按「绳索/自重+下拉」检索 |

## 8. 结果表达（对话式，禁止 JSON 报文）

- 已存在 → "这个动作库里有了：XXX（胸部/杠铃），我把新资料合并进去。"
- 不存在 → "库里没这个动作，我按新动作建档。"
- 不确定 → "我找到两个相近的：A 和 B，你说的是哪个？"
- 回流失败 → "训记里的'XX'我在库里没找到对应动作，要补录吗？这次先不回流这一项。"
