# 健身追踪 - 讯记同步子技能

## 职责

讯记是**可选的外部独立技能**，不是必须。本模块以桥接方式调用讯记 skill 拉取数据，用于填充当日未录入的数据。

桥接三原则：

1. **不直连**：讯记的接口地址、请求参数、报文格式，一律不出现在本技能中
2. **不持有**：讯记的 Key / 凭证，本技能不存、不读、不经手——技能文件与配置文件中都不出现
3. **只桥接**：对讯记 skill 只做三件事——**检测安装 → 调用 → 接收结果**

## 职责边界（禁止越界）

- 讯记数据的查询、写回、鉴权、限频、错误码，**全部归讯记 skill 内部完成**
- 用户提出讯记领域的操作需求（如"帮我把这顿饭记到讯记里"）→ **引导用户使用讯记 skill**，本技能禁止代劳
- 讯记数据缺失时，等待用户补充或留空，**禁止估算、禁止编造**
- 三个讯记 skill 两两独立、互不混用：各自检测、各自降级、Key 各自自管

## 执行流程

### 场景进度

当前场景：gin-fitness-tracker — sync-xunji

Progress:
- [ ] Step 1 发送模块状态反馈 [自动]
- [ ] Step 2 检测讯记 skill 是否可用 [自动]
- [ ] Step 3 调用讯记 skill 拉取数据 [自动]
- [ ] Step 4 对比用户已录入数据 [自动]
- [ ] Step 5 只填充空白字段（不覆盖用户数据） [自动]
- [ ] Step 6 标记数据来源为「讯记同步」 [自动]
- [ ] Step 7 返回结构化结果 [自动]

禁止：
- 不要覆盖用户主动录入的数据
- 不要估算或编造讯记缺失数据
- 不要代劳讯记领域的操作需求

```
被主技能调用
    ↓
① 发送模块状态反馈：🔄 正在同步讯记数据（不覆盖已录入内容）...
    ↓
② 现场检测讯记 skill 是否可用（按技能名检测环境中的安装状态，
   不依赖初始化时的一次性结论）
    ↓ 不可用 → 返回 XUNJI_UNAVAILABLE 错误

   **讯记 skill 不可用时，本步骤不阻塞主流程，输出：**
   `当前阻塞：讯记同步不可用（xunji-xxx skill 未安装）。跳过讯记填充，继续运行。`
③ 调用讯记 skill 拉取数据（身体/饮食/训练）
    ↓
④ 对比用户已录入数据
    ↓
⑤ 只填充空白字段，不覆盖用户数据
   （写入必须经 write-verify 统一入口，不直接写表）
    ↓
⑥ 标记数据来源为"讯记同步"
    ↓
⑦ 返回结构化结果
```

## 返回格式

```json
{
  "status": "success" | "partial" | "failed",
  "module": "sync-xunji",
  "message": "给用户看的自然语言摘要",
  "data": {
    "date": "2026-07-26",
    "filled_by_xunji": ["训练内容", "总热量"],
    "skipped_because_user_entered": ["晨起体重"]
  },
  "errors": []
}
```
