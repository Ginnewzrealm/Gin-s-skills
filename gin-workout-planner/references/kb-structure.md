## 1. 初始化流程

首次使用（用户从未指定知识库路径，或用户说"初始化健身知识库"）时执行：

1. **用户指定知识库路径**：询问用户指定一个本地文件夹路径，给出建议示例，如：
   > "请指定一个本地文件夹路径，用于存放健身知识库。建议示例：`/Users/你的用户名/Documents/fitness-knowledge-base`"
   
   **铁律（违反即 bug）**：
   - 路径必须来自用户明确发出的内容；建议示例只是格式参考，**禁止当成默认值使用**
   - 用户给出路径后，必须复述并请其**二次确认**（"我将以 `XXX` 作为知识库路径，确认吗？"），确认后才继续
   - 用户未回复、回答模糊、或追问两遍仍未给出 → **停下等待，禁止自行编造路径、禁止继续初始化**
2. **创建目录结构**：检查该文件夹并按下表处理：

| 情况 | 处理 |
|------|------|
| 不存在 | 自动创建 |
| 存在且为空 | 按下方架构初始化全部文件夹和文件 |
| 存在且有内容 | 保持现有内容，只补齐缺失的结构，不覆盖已有文件 |

3. **检测训记训练技能依赖（只检测，不存 Key）**：检查用户环境中是否已安装训记训练数据接口技能：
   - **检测方法**：不依赖固定 skill 名。优先尝试以下候选名：
     - `xunji-training`
     - `agents-bridge:xunji-training`
     - 扫描 skills 目录下名称含 `xunji` 且含 `training` 的技能
   - 找到可用技能后，将其 Skill 调用名写入 `_skill-config.json` 的 `xunji_training_skill_name`。
   - 已安装 → 告知一声："检测到训记训练技能（调用名：`{xunji_training_skill_name}`），以后训练数据默认从训记读取，训练计划也能写入训记～"
   - 未安装 → 告知用户："没检测到训记训练技能，训练日记先走'你口述/粘贴'的通道；如需自动读取训练数据或把计划写入训记，请先安装训记训练技能"。**初始化不因此中断，其余功能照常**
   - 健身助手不直接调用训练接口、不保存训练 Key——训练数据的查询与鉴权全部由训记训练技能内部完成，健身助手只调用该技能并接收其结果
3b. **检测训记饮食技能依赖（只检测，不存 Key）**：检查用户环境中是否已安装训记饮食数据接口技能：
   - **检测方法**：不依赖固定 skill 名。优先尝试以下候选名：
     - `xunji-food`
     - `agents-bridge:xunji-food`
     - 扫描 skills 目录下名称含 `xunji` 且含 `food` 的技能
   - 找到可用技能后，将其 Skill 调用名写入 `_skill-config.json` 的 `xunji_food_skill_name`。
   - 已安装 → 告知一声："检测到训记饮食技能（调用名：`{xunji_food_skill_name}`），训练日记会带上今日饮食板块～"
   - 未安装 → 提醒用户："没检测到训记饮食技能，训练日记暂时不含饮食板块；如需启用，请先安装训记饮食技能"。**初始化不因此中断，其余功能照常**
   - 健身助手不直接调用饮食接口、不保存饮食 Key——饮食数据的查询与鉴权全部由训记饮食技能内部完成，健身助手只调用该技能并接收其结果
4. **提问训练目标与训练水平（写入配置）**：用一段话向用户提问，等待回答：
   > "还有两个问题帮我了解你～ ①你的训练目标是哪个：**增力**（冲大重量）、**增肌**（长维度）、还是**肌耐力**（塑形线条）？②你的训练水平是哪个：**新手**＝系统训练不满 3 个月，**中级**＝3 个月到 1 年，**高级**＝1 年以上？"
   - 用户作答 → 写入 `_skill-config.json` 的 `training_goal`、`training_level`
   - 用户不答或回答模糊 → 写默认值（`增肌` + `中级`）并告知："先按增肌+中级给你安排，之后随时说'我想增力'、'我其实是新手'就能改"
4b. **提问训练侧重点（写入 训练侧重点.md，四分区结构见 training-focus.md）**：三轮提问，等待回答：
   - 第一轮（部位级次数档）：
   > "最后定一下训练侧重点，直接回字母就行～ 各部位次数档三选一：**A. 4-8 练力气**　**B. 8-12 练维度**　**C. 12-20 肌肉觉知、控制、耐力与塑形**　**D. 无偏好按默认**。胸部/背部/肩臂部/臀腿部/核心腹部各选哪个？（可简答"胸B 背A 其他D"，全无偏好回"都D"）"
   - 第二轮（细分级 + 部位策略，标签取自 rules.md 目标部位词表）：
   > "再细一点～这些细分部位里有没有想单独定档的？胸部：上缘/下缘/中缝/外缘/整体厚度；肩：前束/中束/后束；臀腿部：臀部整体/上缘/下缘/侧臀/股四头肌/腘绳肌/大腿内侧/小腿；背：上背/宽度/厚度/下背；核心：上腹/下腹/侧腹/核心整体。（可简答"中缝B 侧臀C"）另外：有没有想**加强**、**维持**或**避开**的部位/细分部位？（加强=排序前移；维持=最低限度保持、少练不加重；避开=有伤不练，比如"下背避开"）有没有想**多做/少做/避开**的具体动作？没有就回"跳过"～"
   - 第三轮（整体原则，开放式）：
   > "最后一句～有没有整体的训练原则或目标想让我记住？比如"下半身为主力""上半身不想变厚"这种，随便说，我帮你整理。（没有就回"没有"）"
   - 用户作答 → 按 `references/training-focus.md` 格式写入知识库根目录 `训练侧重点.md` 并复述确认（整体原则提炼为 bullet 写「一、」；部位策略写「二、」；次数偏好单档/双档写「三、」；动作多做/少做/避开写「四、」）
   - 用户不答/全部 D → 创建空骨架文件并告知："以后随时说'记一下我的侧重点'就能补"
   - 格式规范、三档标签与计划联动规则一律以 `references/training-focus.md` 为准
5. **创建配置文件**：在知识库根目录创建 `_skill-config.json`（结构见第 4 节）。
5b. **创建训记写回记录文件**：在知识库根目录创建 `.xunji-writeback/plan-writeback-log.json`，初始内容：

```json
{
  "schema_version": "1.0",
  "records": []
}
```

6. 告知用户：后续会话如换了环境，直接提供知识库路径即可。
7. **环境加固提示（Claude Code 用户，一次性）**：技能已约定"主对话串行执行、禁止子 Agent"，但指令层不是技术锁。建议用户在 Claude Code 的 `settings.json` 权限配置中把 Task 工具加入 deny 列表，从技术上禁用子 Agent：

```json
{
  "permissions": {
    "deny": ["Task"]
  }
}
```

   告知话术："要不要我帮你把子 Agent 功能在 Claude Code 里禁掉？这样以后处理你的动作库就是绝对串行的。"用户确认后指导其修改配置；非 Claude Code 环境跳过本步。

## 3. 动作索引.md 格式（复选框式，两级分类）

**状态用复选框表达：不勾 `- [ ]` = 激活，勾选 `- [x]` = 冷冻。** 利用 Obsidian 对已完成任务的渲染约定：勾选后出现删除线 = 该动作被打入"冷宫"，视觉与语义一致。Obsidian 中复选框可直接点击切换；纯文本中手动改 `x` 即可。

**两级结构：一级标题 = 肌肉部位，二级标题 = 器械，动作行挂在二级标题下。**

二级标题清单（按一级分类固定）：

| 一级分类 | 二级标题 |
|----------|----------|
| 胸部 / 背部 / 肩臂部 / 臀腿部 / 核心腹部 / 全身功能性 | 杠铃、哑铃、史密斯机、悍马机、固定器械、绳索/龙门架、地雷杆、自重、弹力带、弹力绳、悬挂、壶铃（共 12 个） |
| 有氧 | 器械类、自重 |
| 拉伸/筋膜 | 徒手拉伸、泡沫轴/筋膜球、辅助器械拉伸 |
| 热身 | **按肌肉部位分**：胸部、背部、肩臂部、臀腿部、核心腹部、全身（共 6 个） |

初始内容：9 个一级分类、各自全部二级标题，每个二级标题下初始标注「（暂无）」。初始化时必须把全部二级标题列出（即使为空），保证索引骨架完整。

### 行格式（不变）

```markdown
- [ ] [动作名称](./部位文件夹/动作名称.md) ｜ 动作类型 ｜ 最后练习
```

- 不勾 `- [ ]` = 激活；勾选 `- [x]` = 冷冻
- 热身行的类型段填 `热身（适用部位）`，如 `热身（胸部、肩臂部）`——生成计划时凭此匹配，无需打开动作文档
- 最后练习：未练过填 `待记录`；热身行不适用，填 `-`。`待记录` 是字面值，任何位置（含动作文档 frontmatter）都不带方括号，写成 `[待记录]` 属格式错误
- 新增动作：默认不勾（激活）；已冷冻的动作勾选，如 `- [x] [史密斯机推胸](./胸部/史密斯机推胸.md) ｜ 复合动作 ｜ 待记录`；热身行如 `- [ ] [弹力带肩环绕](./热身/弹力带肩环绕.md) ｜ 热身（胸部、肩臂部） ｜ -`
- **热身行归位规则**：适用多个部位的热身动作，放在其第一个适用部位的二级标题下，类型段写全适用部位；同一动作禁止在多个热身二级标题下重复建行。

### 索引维护规则

- **状态以本表为准**：用户直接勾选/取消勾选维护状态；Agent 发现本表与动作文档 frontmatter 不一致时，按本表修正 frontmatter（不勾 = 激活，勾 = 冷冻）
- 新增动作：在对应「部位 + 器械」二级标题下追加一行，默认不勾（激活），最后练习填 `待记录`
- 写完训练日记：把涉及动作行尾的「最后练习」更新为当天日期
- 做计划 / 列清单：只读本表，**不勾行 = 可选动作，勾选行（删除线）= 跳过**

### 行排序规则与巡检（真源）

**排序规则**：每个器械二级标题内部——激活行在前，按「三大项 → 复合动作 → 孤立动作」分层（依行内类型段判定，不翻文档）；冷冻行沉底；同类型内部保持原有先后顺序不动。

**巡检（写后自检）**：任何写索引的场景（入库加行、回流更新日期、状态管理切换）完成后，必须全表巡检一遍。四项职责按固定顺序执行：**格式检查 → 归位检查 → 排序 → 查重标记**（先归位再排序，顺序才有意义）。巡检三条权限铁律：

1. **只搬位置**——重排与归位只允许移动行
2. **不动内容**——禁止删除、禁止修改任何一行的任何字符（动作名/链接/类型段/日期）；巡检后行数必须与巡检前一致，少一行 = 出错，立即回滚并报告用户（例外仅两类：「格式检查」的括号修正、巡检标记（【重复待删】/【待确认】）的追加与移除，见下方对应节）
3. **不碰状态**——复选框的勾/不勾完全是用户的操作（手动或对话指令），巡检一律不许切换；认为某动作该冷冻时只能口头建议

**格式检查（随巡检一并执行）**：索引行「最后练习」列只接受三种值——日期 `YYYY-MM-DD`、字面值 `待记录`、热身行的 `-`。发现 `[待记录]` 等带括号写法 → 授权自动修正为 `待记录`（仅去括号，这是「不动内容」铁律的第一项授权例外；修正前后行数不变，不触碰该行其他任何字符）。除此之外的任何格式异常不自动改，原样保留并报告用户。

**归位检查（随巡检一并执行）**：检查每行是否放在正确的「部位 + 器械」标题下，三级判定，能不翻文档就不翻：

- **L1 结构校验（每行必查，不翻文档）**：行内链接路径的部位文件夹 == 所在一级标题（`./胸部/xx.md` 必须在 `## 胸部` 下；热身行路径 `./热身/` 且在 `## 热身` 下）；链接文件名 == 行显示动作名。不符 → 进 L3 翻文档确认
- **L2 器械归位（按名称判定，不翻文档）**：从动作名提取器械词，按 `name-matching.md` 器械别名表标准化后应对应所在 `###` 二级标题；明确不符（如「哑铃飞鸟」在 `### 杠铃` 下）→ 自动移到正确二级标题并报告（移动属「只搬位置」，铁律允许）
- **L3 部位归位（仅 L1 不符或名称与部位明显冲突时翻文档）**：读文档「目标肌肉」字段确定应属部位；只是索引行放错、文档位置正确 → 自动移行到正确「部位 + 器械」标题下并报告；文档本身就放错文件夹（目标肌肉与文件夹不符）→ 不自动动（涉及移文件改链接），报告用户处理
- **目标标题处理**：目标器械二级标题不存在 → 按 12 类器械表新建标题再移入；部位一级标题对不上 → 属异常，报告用户
- **待确认标记**：名称看不出器械/部位、无法判定的行 → 不猜不移，行尾追加 `【待确认】` 标记并列入报告，由用户手动归位；用户归位后自行去掉标记（或对话指令 Agent 去掉）

**查重标记（随巡检一并执行）**：全表两两比对，判定方法复用 `name-matching.md`（同一套四原则与五步流程，比对范围从「新动作 vs 索引」变为索引内部互比）。发现重复（确定或疑似）时：

- 在**建议删除行**的行尾追加标记：`【重复待删：与「另一动作名」疑似同一动作】`（保留行不标记）
- 保留行判定：有训练记录（最后练习为日期）的优先留 > 都是/都不是 `待记录` 则符合命名规范的优先；拿不准就两行都标，最终由用户拍板
- 对话中列出重复对 + 判定依据 + 保留建议；**删行永远是用户手动操作**，巡检只标记、不删除
- 用户复核认为不是重复 → 用户对话指令后 Agent 才可去掉标记
- 追加/去除标记（【重复待删】【待确认】）属「不动内容」铁律的第二类授权例外：只许在行尾追加或移除标记文本，不得改原行任何字符
- 善后提醒：被删行若有训练记录，提示用户先把最后练习日期并入保留行；若有动作文档，提示合并或留存备查，禁止默默删文档

### 训练日记命名

```
02-训练日记/YYYY-MM-DD_部位-训练日记.md
```
示例：`2025-03-15_胸部-训练日记.md`（部位名用索引一级标题的文件夹名，如 `臀腿部`、`核心腹部`）

## 4. 配置文件 _skill-config.json

初始化时在知识库根目录创建：

```json
{
  "knowledge_base_root": "{用户指定的路径}",
  "training_goal": "增肌",
  "training_level": "中级",
  "xunji_training_skill_name": "agents-bridge:xunji-training",
  "xunji_food_skill_name": "agents-bridge:xunji-food"
}
```

| 字段 | 说明 |
|------|------|
| `knowledge_base_root` | 知识库根路径；各子路径（01-训练动作库、02-训练日记、03-训练计划等）按固定目录结构从根路径推导，不再单独存配置 |
| `training_goal` | 训练目标：`增力` / `增肌` / `肌耐力`，默认 `增肌`。初始化时提问确定；每次输出训练计划时合并确认（见 plan-output.md 步 5-5c），用户口头更改（"这段想增力"）→ 更新字段。是无侧重点时的全局默认区间来源；侧重点优先于它，见 `references/training-focus.md` |
| `training_level` | 训练水平：`新手` / `中级` / `高级`，默认 `中级`。初始化时附定义让用户自选（新手＝系统训练不满 3 个月；中级＝3 个月到 1 年；高级＝1 年以上），用户口头更改 → 更新字段。详细用法见 `references/volume-params.md` |
| `xunji_training_skill_name` | 训记训练技能的 Skill 调用名。初始化时检测当前环境并写入，后续调用 `references/trains-train-writeback.md` 时读取使用。**不要硬编码**，若技能被移动/重命名，重新初始化或手动更新本字段 |
| `xunji_food_skill_name` | 训记饮食技能的 Skill 调用名。初始化时检测当前环境并写入，后续调用 `references/trains-diet-bridge.md` 时读取使用。**不要硬编码** |

> ⚠️ **字段清理通用规则（v1.22.2 起）**：每次读取 `_skill-config.json` 时核对字段清单——凡上表五个字段以外的字段一律视为旧版残留，处理顺序：① 值有归属的先迁移（如 `priority_muscles` 非空 → 并入 `训练侧重点.md`「二、部位策略」加强行，真源 `references/training-focus.md`）→ ② 报告用户该字段来历与处理方式 → ③ 用户确认后删除字段（Key 类字段如 `trains_api_key` 无归属，直接报告并删除；`priority_muscles` 为空字段时同样直接删除）。禁止静默删除，也禁止留着不管。

后续每次启动先读本文件：取 `knowledge_base_root` 推导各子路径；用户另给路径时以用户给的为准并更新本文件。
