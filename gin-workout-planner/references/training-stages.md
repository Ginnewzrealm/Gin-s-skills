# 训练阶段体系（真源）

> 何时读我：出训练计划定负荷策略与确认阶段、写日记复盘定容错口径、动作问答按阶段给侧重、用户切换阶段时，必须先读本文件。
> 本文件是「训练阶段」的唯一真源：阶段定义、字段约定、切换规则、场景联动，其他文件只引用不复制。

## 1. 字段约定

- 字段名：`训练阶段`，存于**动作文档 frontmatter**（与计重方式同层），不进索引表
- 取值仅三种：`学习期` / `渐进期` / `精细优化期`
- 新建动作默认 `学习期`；格式预检将其列入 frontmatter 必填字段
- 阶段是「当前状态标签」，不是等级——支持回退与循环（如精细优化后可回渐进期）

## 2. 三阶段定义

| 阶段 | 核心任务（唯一） | 负荷策略 | 容错标准 | 典型进入信号 |
|------|------------------|----------|----------|--------------|
| 学习期 | 动作模式，重量必须让步 | 保守轻重量，优先保证形态 | **低容错近乎零妥协**：一加重量就明显代偿/失控/关节跑偏 → 判定重量超标 | 新动作默认 |
| 渐进期 | 守住框架，可控提升负荷 | 按估算 1RM × 百分比正常推进 | **适度容错**：组末吃力、酸胀、小幅形变 = 正常疲劳；大幅度代偿必须停止 | 轻载下形态稳定 |
| 精细优化期 | 目标肌张力分配，不堆重量 | 维持当前重量，打磨顶峰收缩/离心减速/拉伸位停顿/握距脚位等细节（技术选用见 techniques.md） | **高标准内部容错**：外观标准不算满分，看压力是否精准落在目标肌、协同肌是否抢力 | 重量稳步上涨但肌肉感受差、进步变慢；打磨见效后可回渐进期 |

一个动作同一时期只能有一个核心任务——阶段划分就是强制做优先级取舍。

## 3. 切换规则（权限铁律）

- **阶段切换永远是用户操作**：用户口头指令（"我卧推进入渐进期了"）→ Agent 更新该动作 frontmatter 并复述确认
- Agent 可依据数据**建议**（如"该动作累计次数与 1RM 稳步上涨，可考虑进渐进期"），**禁止自动切换**
- 巡检不碰训练阶段（与复选框同级，属用户操作域）

## 4. 计划场景联动

- 出计划时列出本次涉及动作的当前训练阶段，一句话向用户确认（"卧推目前在渐进期、飞鸟在学习期，要改说一声"）；用户口头更改 → 先更新 frontmatter 再继续
- 负荷策略按阶段执行第 2 节对应列：学习期 → 保守重量；渐进期 → 1RM 百分比正常推进；精细优化期 → 维持重量，把打磨技术写进动作要点
- **计划正文阶段标注（固定格式）**：动作名后挂阶段标签（如「杠铃卧推（渐进期）」），动作要点下配一行阶段口径；口径文案按下表**逐字固定输出，禁止现编改写**：

| 阶段 | 阶段口径（固定文案） |
|------|----------------------|
| 学习期 | 本阶段只求动作标准：重量保守，形态 > 次数 > 重量；一加重量就代偿，立刻降回去 |
| 渐进期 | 本阶段主攻稳步加重：按计划推进重量/次数；组末小幅形变是正常疲劳，大幅代偿才停 |
| 精细优化期 | 本阶段打磨受力质量：重量冻结不涨，专注目标肌精准受力；协同肌抢力就调细节，不加重 |

- 阶段标注必须**实时读动作文档 frontmatter**，禁止凭记忆或上次计划填写；精细优化期动作另从文档「四、动作过程」三阶段注意点与「六、动作速度」中提取孤立辅助肌/突出目标肌的具体提示写进动作要点

## 5. 日记场景联动（容错口径）

复盘「不足与改进」按动作当前阶段判定：

- **学习期**：明显代偿/失控/关节跑偏 = 问题，判定重量超标，建议降重保形态
- **渐进期**：组末几次小幅形变 = 正常疲劳，不写为问题；大幅度代偿才记
- **精细优化期**：外观标准但目标肌受力被协同肌抢 = 问题，建议调整细节而非加重
