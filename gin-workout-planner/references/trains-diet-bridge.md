# 训记饮食技能 桥接约定

> 触发条件：训练日记场景写「今日饮食」板块、或初始化做依赖检测时，必须先读本文件。
> 前置条件：用户环境中已安装「训记饮食技能」。

## 一、职责边界

调用方技能（本技能）负责：
- 检测「训记饮食技能」是否已安装
- 构造调用参数并发起调用
- 接收返回结果并按本技能规则使用（写入训练日记「今日饮食」板块）

被调用方技能（训记饮食技能）负责：
- 饮食数据的查询、写回、鉴权、限频
- 返回数据的格式整理
- 错误原因的定义与返回

本技能明确不执行以下操作：
- 不直接调用任何饮食接口
- 不存储或读取任何饮食相关凭证；技能文件与 `_skill-config.json` 中都不出现饮食 Key
- 不替代「训记饮食技能」完成饮食数据的记录与修改
- 与「训记训练技能」互为独立（约定见 `trains-train-bridge.md`），两者都只检测安装 + 调用 + 接收结果，互不混用

## 二、依赖检测

检测方式：初始化或进入训练日记场景时，检测「训记饮食技能」是否存在于当前用户环境。

- 已安装 → 继续调用流程，取「今日饮食」板块数据
- 未安装 → 提醒用户安装「训记饮食技能」并说明安装途径；同时启用备用通道：日记饮食板块填「未配置」，主流程不中断。禁止尝试调用其任何功能，禁止模拟或伪造返回结果

## 三、输入参数

| 参数名 | 类型 | 必填 | 取值范围/格式 | 说明 |
|--------|------|------|---------------|------|
| date | string | 是 | YYYY-MM-DD | 要查询的饮食日期（与训练日记同日） |

## 四、输出结果

| 字段名 | 类型 | 存在条件 | 说明 |
|--------|------|----------|------|
| status | string | 始终存在 | "success" 表示成功，"error" 表示失败 |
| total_calories | number | status = "success" 且当日有记录 | 总热量（kcal），按返回口径原样记录 |
| protein | number | status = "success" 且当日有记录 | 蛋白质（g），按返回口径原样记录 |
| carbs | number | status = "success" 且当日有记录 | 碳水化合物（g），按返回口径原样记录 |
| fat | number | status = "success" 且当日有记录 | 脂肪（g），按返回口径原样记录 |
| error_msg | string | status = "error" | 用户可理解的错误原因描述，原样展示 |

## 五、异常处理

| 异常情况 | 处理方式 |
|----------|----------|
| 训记饮食技能未安装 | 板块填「未配置」，提醒用户安装；不阻塞训练日记主体 |
| 调用失败/返回 status = "error" | 板块填「无记录」并原样告知错误原因；禁止自动重试，禁止修改或篡改错误信息；不阻塞训练日记主体 |
| 当日无饮食记录 | 板块填「无记录」，属正常情况，不算失败 |
| 返回结果缺少某项营养素字段 | 该项填「待补充」；禁止估算，禁止从其他来源编造数据补全 |
| 用户要求记录/修改饮食 | 引导用户使用「训记饮食技能」，本技能禁止代劳 |
